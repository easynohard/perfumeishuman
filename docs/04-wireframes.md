## 0. 읽는 법 · 공통 규칙

- 모든 화면은 **모바일 360px 폭 기준**(N1). 관리자 3종만 데스크톱 우선.
- 박스 다이어그램은 저해상도 구조 정의다 — 색·타이포·아이콘·간격은 8단계에서 확정한다.
- 모든 탭 가능한 요소는 터치 타깃 44px 이상(N1). 본문 텍스트 16px 이상(N7).
- `┃ … ┃` 표시는 **하단 고정(sticky) 요소**, `┈┈┈` 은 카드 내부 구분선, `╌╌╌` 은 MVP 비노출 예약 슬롯.

### 컨셉 언어 (확정)

UI 문구는 "사람 소개하듯 말하는" 톤으로 통일한다 (1단계 §4.4).

| 위치 | 일반적 표현 | 이 서비스의 표현 |
|---|---|---|
| 향수 상세의 시향기 목록 제목 | 리뷰 N개 | **{향수 이름}(이)가 사람이라면 (N)** |
| 시향기 상세의 태그 답변 영역 | 태그 | **이 사람의 프로필** |
| 시향기 상세 하단 목록 | 같은 향수 다른 리뷰 | **이 향수의 다른 페르소나 (N)** |
| 작성 폼 등록 버튼 | 등록 | **내가 아는 {향수 이름}은/는 이래요** |
| 향수 상세의 스펙 정보(계열·노트) | 상세 정보 | **필요없는 정보들** (접힘 버튼) |
| 시향기 0개 빈 상태 | 아직 리뷰가 없어요 | **이 향수에 영혼을 불어넣어 사람으로 만들어주세요** |
| 본인 글 추천 버튼 자리 | (비활성) | **내가 소개한 사람이에요** |

- `{향수 이름}` 자리에는 실제 향수명이 들어간다. 한국어 조사((이)가 · 은/는)는 향수명의 받침 유무에 따라 자동 처리한다 — 구현 규칙은 10단계 코딩 컨벤션에서.

## 1. 공통 컴포넌트

### 1.1 상단 헤더

```
┌──────────────────────────────┐
│ perfumeishuman          [🔍] │   홈 3탭: 로고(=홈) + 검색 아이콘
│ ←                       [🔍] │   하위 화면: 뒤로가기 + 검색 아이콘
└──────────────────────────────┘
```

- 검색 아이콘은 모든 화면 상단에 있고(A1), 탭하면 전체 화면 검색 오버레이 `/search` (3단계 결정 4).
- 시향기 상세만 `[⋯]` 메뉴가 추가된다 (§2.7).

### 1.2 하단 탭바 (모바일 전 화면 공통)

```
┌──────────────────────────────┐
│   홈      ( ✍ 쓰기 )    MY   │
└──────────────────────────────┘
```

- **쓰기가 중앙 강조 탭** — 서비스의 심장(N3, 3단계 결정 1). 시각적 강조(원형 버튼 등)는 8단계에서.
- 쓰기 탭: 멤버·게스트 모두 → `/write` (향수 선택부터). 게스트에게도 로그인 벽 없음 — 로그인 바텀시트(§3)는 등록(제출) 시점에만 (§1.4).
- MY 탭: 멤버 → `/me`, 게스트 → `/me`의 게스트 상태(로그인 버튼 노출, §4.2).
- 관리자 화면과 검색 오버레이에는 탭바 없음.

### 1.3 시향기 카드 (피드·목록 공용 컴포넌트)

```
┌──────────────────────────────┐
│ 딥티크 · 오 로즈              │  ← ⓐ 브랜드 · 향수명 (맨 위 — 확정)
│ ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈ │
│ “첫 출근날 긴장한 신입사원    │  ← ⓑ 자유 서술 전문
│  같은 향이에요. 단정한데      │     (≤100자, 잘림 없음 — B1)
│  손끝은 떨리는.”             │
│                              │
│ 20대 · 차분한                │  ← ⓒ 대표 태그 (나이·성격
│ 수줍은베르가못        ♥ 128   │     질문에서 각 1개씩)
└──────────────────────────────┘  ← ⓓ 작성자 닉네임 · 추천 수
```

- 카드 전체가 탭 영역 → 시향기 상세 (B1). 1열 레이아웃.
- **목록은 10개씩 노출 + [더보기] 버튼** — 무한 스크롤 아님 (§6-10). 시향기 카드가 나오는 모든 목록(홈 피드·향수 상세·작성자 프로필·MY·시향기 상세 하단)에 공통 적용.
- **변형 A (기본)**: 위 그대로 — 홈 피드, 작성자 프로필, MY.
- **변형 B (같은 향수 문맥)**: ⓐ 브랜드·향수명 줄 생략 — 향수 상세의 목록, 시향기 상세 하단의 "이 향수의 다른 페르소나" (같은 향수라 중복 정보이므로).
- 대표 태그는 나이·성격에서 각 1개 (ADR 0007 — 태그 질문 2종으로 축소).

### 1.4 로그인 게이트 트리거 규칙 (화면 아님)

| 트리거 | 게스트일 때 | 로그인 완료 후 복귀 (C1) |
|---|---|---|
| 시향기 등록(제출) — 작성 폼(`/write`)에서 [등록]을 눌렀을 때 | 바텀시트 | 입력해 둔 내용 그대로 자동 등록 → 시향기 상세 (D1) |
| 추천 버튼 | 바텀시트 | 그 시향기로 복귀 + **추천 자동 반영** (C2, FL4) |
| MY 탭의 로그인 버튼 | 바텀시트 | `/me` 멤버 상태 |

**작성 폼(`/write`) 자체는 게스트도 진입해 입력할 수 있다** — 향수 상세 고정 바 · 쓰기 탭 · 빈 상태 버튼 중 어느 경로로 들어와도 로그인 벽 없이 곧장 폼이 열린다. 위 표의 게이트는 화면 진입이 아니라 **등록(제출) 버튼**을 누르는 순간에만 나타난다.

멤버는 게이트 없이 그대로 통과. 열람 경로에는 어떤 로그인 벽도 없다 (N2).

### 2.4 검색 `/search` (A1 · M1)

전체 화면 오버레이 — 어느 화면에서든 검색 아이콘으로 진입, URL 유지 (3단계 결정 4).

```
┌──────────────────────────────┐
│ ← ┌────────────────────────┐ │
│   │ 🔍 향수·브랜드 검색     │ │ ← 진입 즉시 키보드 포커스
│   └────────────────────────┘ │
├──────────────────────────────┤
│ ─ 입력 전: 인기 향수 ─        │
│  ▢ 오 로즈 · 딥티크  시향기 12│
│  ▢ 블랑쉬 · 바이레도 시향기 9 │
│             ⋮                │
│                              │
│ ─ 입력 중: 결과 (부분일치) ─  │
│  향수                        │
│  ▢ 오 로즈 · 딥티크  시향기 12│ ← 이미지·향수명·브랜드·시향기 수
│  브랜드                      │
│  ▢ 딥티크            향수 18 │
│                              │
│ ─ 결과 없음 ─                │
│  “아직 등록되지 않은          │
│   향수예요”                  │
│  + 인기 향수 목록 (위와 동일)  │ ← 빈 화면으로 끝내지 않음 (A1)

│ ┌──────────────────────────┐ │

│ ┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈┈ │

├──────────────────────────────┤
│ ┃  ✍ 이 향수의 시향기 쓰기  ┃ │ ← 하단 고정 바 (§6-5)

```

- 정렬 토글(추천순/최신순)은 **첫 번째 카드를 포함한 목록 전체**에 적용된다 — 상단에 고정되는 대표 카드 없음.
- "필요없는 정보들"은 스펙(계열·노트)을 부록으로 밀어내는 컨셉 선언 — 시향기가 주인공 (1단계 §1.1).
- **이미지 폴백은 선택이 아니라 필수다** ([ADR 0009](./adr/0009-perfume-image-sourcing-and-takedown.md) §5). 권리 이의가 들어오면 이미지를 즉시 내려야 하는데, 폴백이 없으면 화면이 깨져서 운영자가 내리기를 망설이게 된다. 검색 결과(§2.4)·브랜드 상세(§2.5)·계열 상세(§2.6)의 향수 항목에도 같은 폴백을 적용한다.
- 권리 고지 푸터는 시향기 목록 아래, 하단 고정 바 위에 둔다 — 읽는 흐름을 방해하지 않되 모든 향수 화면에서 접근 가능해야 한다 (N13).
- 고정 바 탭 → 게스트도 로그인 벽 없이 이 향수가 선택된 채 `/write` 진입 → [등록] 시도 시에만 로그인 바텀시트 → 자동 등록 (FL3, D1).

**`/help` 전용 구성** — 조문 대신 3개 블록으로 나눈다.

```

├──────────────────────────────┤

## 3. 로그인 바텀시트 (화면 아님 — 오버레이)

```
┌──────────────────────────────┐
│  (현재 화면이 뒤에 흐리게)     │
│                              │
│ ╭──────────────────────────╮ │
│ │            ──            │ │ ← 드래그 핸들 (내려서 닫기)

│ │                          │ │
│ │ ┌──────────────────────┐ │ │
│ │ │  카카오로 시작하기     │ │ │ ← 소셜 1탭 (공급자는 9단계
│ │ └──────────────────────┘ │ │    확정 — C1)
│ │                          │ │
│ │  로그인하면 하던 일로      │ │
│ │  바로 돌아가요            │ │ ← 복귀 보장 안내 (N2)
│ │                          │ │
│ │  시작하면 이용약관과       │ │ ← 동의 고지 (F1) — 별도 화면·
│ │  개인정보처리방침에        │ │    체크박스 없이 버튼 아래 1블록
│ │  동의하는 것으로 봅니다.    │ │    [약관]·[방침] 은 링크
│ │  탈퇴 후에도 작성한        │ │

│ ╰──────────────────────────╯ │    이 문장이 빠지면 안 됨

```

| 트리거 | 헤드라인 문구 (예시 — 8단계에서 확정) |
|---|---|
| 쓰기 | 이 사람을 소개하려면 3초면 충분해요 |
| 추천 | 이 사람에게 추천을 보내려면 로그인이 필요해요 |

- 독립 페이지 없음. 콜백 라우트 `/auth/callback`만 존재 (3단계 결정 3).
- 최초 로그인 시 닉네임 자동 생성 — 생성 규칙은 6단계 (C1, 2단계 미해결 3).
- **동의 고지는 버튼 아래 텍스트 블록으로만 처리한다** — 별도 동의 화면도, 체크박스 탭도 추가하지 않는다. "소셜 1탭"이라는 전환 설계(N2·N3)를 지키면서 고지 의무(M11)를 충족하는 지점이다 (F1).
- **"탈퇴 후에도 시향기는 익명으로 남는다"는 문장은 필수다.** 이 고지가 있어야 [ADR 0008](./adr/0008-anonymized-retention-on-withdrawal.md)의 탈퇴 후 콘텐츠 보존이 성립한다. 문구를 다듬을 수는 있어도 삭제할 수 없다.
- 약관·처리방침 링크를 탭하면 `/terms`·`/privacy`가 열리고, **돌아왔을 때 바텀시트와 직전 행동(작성 중이던 내용 포함)이 유지된다** (F1·F2 AC).

│ │  글을 지우고 싶다면        │ │ ← 대안 제시 — 탈퇴 전에만
│ │  탈퇴 전에 먼저 삭제하세요 │ │    가능하다는 안내
│ │                          │ │
│ │  ☐ 위 내용을 확인했어요    │ │ ← 체크해야 아래 버튼 활성
│ │ ┌──────────┐┌──────────┐│ │
│ │ │   취소    ││  탈퇴하기 ││ │ ← 취소를 왼쪽·기본 강조
│ │ └──────────┘└──────────┘│ │
│ ╰──────────────────────────╯ │
└──────────────────────────────┘

─ 게스트 상태 ─
┌──────────────────────────────┐
│ MY                      [🔍] │
├──────────────────────────────┤
│                              │
│   내가 소개한 사람들과        │
│   받은 추천을 볼 수 있어요    │
│                              │
│  ┌────────────────────────┐ │
│  │      로그인하기         │ │ ← 탭 → 로그인 바텀시트 (§3)
│  └────────────────────────┘ │
├──────────────────────────────┤
│   홈      ( ✍ 쓰기 )    MY   │
└──────────────────────────────┘
```

- 삭제는 확인 다이얼로그를 거친다 (D2).
- 정책 링크와 탈퇴는 **화면 맨 아래, 작게** 둔다 — 법적 접근성은 확보하되 MY의 주인공(받은 추천·내 글)을 가리지 않는다 (3단계 결정 6).
- **탈퇴는 독립 화면이 아니라 확인 모달이다** (3단계 결정 7, F3). 로그인을 바텀시트로 처리한 것과 같은 원칙.
- 모달의 세 항목은 순서가 중요하다 — "삭제됩니다"(안심) → "남아요"(예상 밖) → "되돌릴 수 없어요"(경고). 사용자가 놀랄 정보를 결정 직전에 배치한다.
- 체크 없이는 탈퇴 버튼이 비활성이다. 실수 탈퇴는 복구할 수 없으므로 마찰을 의도적으로 남긴다 (ADR 0008 Consequences).
- 탈퇴 완료 후 홈(`/`)으로 이동하며 로그아웃 상태가 된다 (F3 AC).

## 5. 관리자 화면 (3 — 데스크톱 우선, 별도 URL 직접 진입)

일반 내비게이션과 연결되지 않는다. 권한 플래그 검사 후 진입 (E1). 좌측 공통 메뉴로 3개 화면 간 이동.

### 5.1 시향기 관리 `/admin/reviews` (E1 · M9)

```
┌──────────┬───────────────────────────────────────────┐
│ 시향기    │ 시향기 관리                                │
│ 카탈로그  │ ┌───────────────┐ [최신순 ▾]              │
│ 신고      │ │ 🔍 작성자·향수  │                        │
│          │ └───────────────┘                         │
│          │ ┌─────────────────────────────────────┐   │
│          │ │ 작성일  작성자   향수    서술(요약)   │   │
│          │ │ 신고수  ♥   [보기][수정][삭제]        │   │
│          │ │ ──────────────────────────────────  │   │
│          │ │ 8.9   수줍은…  오 로즈  “첫 출근날…”  │   │
│          │ │ 0    128   [보기][수정][삭제]        │   │
│          │ │             ⋮                       │   │
│          │ └─────────────────────────────────────┘   │
└──────────┴───────────────────────────────────────────┘
```

- 삭제 시 **사유 메모 입력 모달** — 관리자 삭제는 일반 삭제와 구분 기록 (E1).
- 수정은 멤버 작성 폼과 동일한 폼을 재사용.

### 5.2 향수·브랜드 관리 `/admin/catalog` (E2 · S4)

```
┌──────────┬───────────────────────────────────────────┐
│ 시향기    │ 카탈로그 관리      [브랜드] [향수]  ← 탭    │
│ 카탈로그  │ ┌───────────────┐        [+ 향수 등록]     │
│ 신고      │ │ 🔍 검색        │                        │
│          │ └───────────────┘                         │
│          │ ┌─────────────────────────────────────┐   │
│          │ │ 이미지 향수명   브랜드  계열  시향기수 │   │
│          │ │ [수정][삭제]                         │   │
│          │ │ ──────────────────────────────────  │   │
│          │ │ ▢   오 로즈   딥티크  플로럴   12    │   │
│          │ │ [수정][삭제]                         │   │
│          │ │             ⋮                       │   │
│          │ └─────────────────────────────────────┘   │
│          │ [브랜드 이미지 일괄 비공개 ▾]  ← 권리 대응  │
└──────────┴───────────────────────────────────────────┘

─ 향수 등록·수정 모달 (이미지 부분만) ─
┌───────────────────────────────────────┐
│  이미지                                │
│  ┌─────────────────────────────────┐  │
│  │  [파일 선택]                     │  │
│  └─────────────────────────────────┘  │
│  원본 출처 URL *                       │ ← 필수 (ADR 0009 §3)
│  ┌─────────────────────────────────┐  │
│  │ https://...                     │  │
│  └─────────────────────────────────┘  │
│  ⚠ 흰 배경 단순 팩샷만 사용하세요.      │ ← 수집 기준 상시 안내
│    연출컷·모델컷·워터마크 이미지는       │
│    등록할 수 없습니다.                  │
│                                       │
│  권리 상태: [정상 ▾]                   │ ← 정상/이의접수/비공개/영구제거
│  수집일: 2026-08-16 (자동)             │
└───────────────────────────────────────┘
```

- 등록/수정은 모달 폼 — 브랜드(이름·로고), 향수(이름·브랜드·이미지·계열·노트) (E2).
- **시향기가 달린 향수 삭제 시 경고 모달** — 시향기 수를 명시하고 재확인 (E2).
- 초기 시딩(인기 향수 100~300개)은 이 화면 또는 스크립트로 (E2, 1단계 §4.1).
- **이미지 등록 시 원본 출처 URL이 필수다** ([ADR 0009](./adr/0009-perfume-image-sourcing-and-takedown.md) §3). 이 기록이 없으면 권리 이의가 들어왔을 때 대상 이미지를 특정할 수 없어 "즉시 제거" 원칙이 실행 불가능해진다.
- 수집 기준(단순 팩샷만) 안내를 입력 폼에 상시 노출한다 — 등록 시점에 판단해야 하는 유일한 사람이 관리자이기 때문이다.
- **재수집 금지 목록**에 등재된 브랜드·제품을 등록하려 하면 경고가 뜬다 (`docs/legal/image-rights-and-takedown.md` §5.2).
- **브랜드 단위 이미지 일괄 비공개** 기능은 브랜드 차원의 이의 제기에 대응하는 수단이다. 비공개 시 해당 향수들은 자동으로 텍스트 카드 폴백으로 전환된다.

## 6. 이번 단계에서 확정된 결정 (2026-08-14 사용자 승인)

> ⚠️ 2026-08-16 결정으로 항목 7이 뒤집혔다. 상세는 [ADR 0007](./adr/0007-reduce-tag-questions-to-two.md) 참고 — 이 문서의 관련 화면(§1.3·§2.8·§4.1)은 이미 최신 상태로 반영됨.

1. **상단 탭 라벨**: 피드 / **브랜드로 찾기** / **계열로 찾기** — "찾기"를 라벨에 노출해 탐색 탭임을 즉시 전달.
2. **홈 피드는 추천순 단일 정렬** — 최신순 토글 없음. ⚠️ 2단계 B1의 "최신순 전환 가능"을 일부 변경하는 결정 (사용자 확정). 향수 상세의 목록(B2)에는 추천순/최신순 토글 유지.
3. **시향기 카드는 브랜드·향수명이 맨 위** — 자유 서술보다 먼저. 같은 향수 문맥(향수 상세·"이 향수의 다른 페르소나")에서는 이 줄을 생략한 변형 B 사용.
4. **향수 상세의 스펙 정보는 "필요없는 정보들" 접힘 버튼 뒤로** — 계열 칩·노트·외부 구매 링크 슬롯(N12)을 펼침 영역에 수납. 버튼 바로 아래에 시향기 목록 시작.
5. **"시향기 쓰기"는 하단 고정 바** — 향수 상세에서 스크롤과 무관하게 상시 노출 (B2 요건 충족 방식 확정).
6. **성격 태그 12개 세트** — 차분한·장난기 많은·도도한·다정한·신비로운·시크한·순수한·자유로운·섹시한·지적인·상큼발랄한·우아한 (다중 선택, 최대 3개).
7. ~~**"어울리는 사람"은 연령대 × 성별 이미지 두 축** — 연령대 5구간(10대~50대+) + 성별 이미지 3종(여성적/남성적/중성적), 각각 복수 선택.~~ → 2026-08-16 ADR 0007로 "만나는 상황"과 함께 질문 자체가 삭제됨 (의인화 컨셉과 어긋남).
8. **시향기 상세의 태그 표시는 "이 사람의 프로필" 표 형태** — 질문별 항목명·답을 줄맞춰 인물 소개 카드처럼.
9. **컨셉 언어 확정 (§0 표)** — 시향기 목록 제목 "{향수 이름}(이)가 사람이라면", 하단 목록 "이 향수의 다른 페르소나", 등록 버튼 "내가 아는 {향수 이름}은/는 이래요", 빈 상태 "이 향수에 영혼을 불어넣어 사람으로 만들어주세요".
10. **시향기 목록은 10개씩 + [더보기] 버튼** — 무한 스크롤 아님. 시향기 카드가 나오는 모든 목록에 공통 적용 (B1의 "무한 스크롤 또는 더보기" 중 더보기로 확정).
11. **질문 카드 버튼과 유도 질문 말풍선은 자유 서술 입력칸 바로 아래** — 입력하다 막힌 시점의 시선 위치에 배치. 태그 질문은 각 최소 1개 필수 유지 (D1 그대로 — 논의 후 원안 유지로 재확정). 질문 종수는 이후 2종으로 축소됨(ADR 0007).

### 추가 확정 (2026-08-16 — 법적 준수 소급 반영) ✅

12. **로그인 바텀시트의 동의 고지는 버튼 아래 텍스트 블록** — 별도 동의 화면·체크박스 없이 처리해 "소셜 1탭" 전환 설계를 지킨다. **"탈퇴 후에도 시향기는 익명으로 남는다"** 문장은 [ADR 0008](./adr/0008-anonymized-retention-on-withdrawal.md)의 법적 전제이므로 삭제 불가 (§3, F1).
13. **회원 탈퇴는 MY 안의 확인 모달** — 독립 화면 없음(3단계 결정 7). 모달은 "계정 삭제 → 글은 남음 → 되돌릴 수 없음" 순서로 고지하고, 확인 체크 전에는 탈퇴 버튼이 비활성이다 (§4.2, F3).
14. **향수 이미지 폴백은 필수 요소** — 이미지가 없거나 권리 이의로 제거되면 향수명·브랜드명 텍스트 카드로 대체된다. 향수 상세·검색·브랜드 상세·계열 상세에 공통 적용 ([ADR 0009](./adr/0009-perfume-image-sourcing-and-takedown.md) §5).
15. **향수 상세 하단에 상표 권리 고지 + 권리 침해 신고 링크** — 모든 향수 화면에서 신고 창구에 접근 가능해야 한다 (§2.7, N13).
16. **관리자 향수 등록 시 이미지 원본 출처 URL 필수** — 이 기록이 "이의 시 즉시 제거"의 실행 조건이다. 수집 기준 안내를 입력 폼에 상시 노출 (§5.2, ADR 0009 §3).
17. **정책 페이지 3종은 공유 템플릿 + 하단 탭바 없음** — 뒤로가기로 직전 상태(작성 중 내용·열린 바텀시트)에 복원되는 것이 요건이다 (§2.10~2.12).
