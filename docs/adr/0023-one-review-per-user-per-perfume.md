# 0023. 한 사람은 한 향수에 시향기를 1개만 쓸 수 있다

- Status: **Accepted** (2026-10-30 확정)
- 관련 문서: [0011-soft-delete-reviews.md](./0011-soft-delete-reviews.md), [0016-aggregate-update-and-soft-delete-scope.md](./0016-aggregate-update-and-soft-delete-scope.md), [04-wireframes.md](../04-wireframes.md) §2.7·§4.1, [05-data-model.md](../05-data-model.md), [06-erd.md](../06-erd.md) (`post`), [07-api-spec.md](../07-api-spec.md) §2

## Context

07 §2의 화면별 커버리지 대조 중, 같은 사용자가 같은 향수에 시향기를 여러 개 쓸 수 있는지가 02·04·05·06 어디에도 정의되어 있지 않음을 발견했다. 정의가 없으면 `POST /reviews`의 중복 처리, "시향기 쓰기" 버튼의 동작, 작성 폼의 향수 검색 결과 표시가 모두 정해지지 않는다. 사용자가 규칙을 확정했다.

## Decision

1. **한 사람은 한 향수에 시향기를 1개만 쓸 수 있다.** 서로 다른 향수에는 각각 쓸 수 있다.
2. 이미 쓴 향수에서 "시향기 쓰기"를 누르면 작성 화면으로 보내지 않고 **"이미 소개했어요" 안내**를 띄운다. 수정 화면으로 보내지 않는다.
3. 서버는 규칙을 최종 방어선으로 막는다. `POST /reviews`가 중복이면 **409 `ALREADY_REVIEWED`**.
4. 회원에게 보여주는 향수 응답(향수 상세, 작성 폼의 향수 검색)에는 **내 시향기 슬러그(`my_review_slug`, 없으면 `null`)** 를 포함해, 화면이 쓰기 전에 안내를 띄울 수 있게 한다.
5. **소프트 삭제된 시향기는 개수에 포함하지 않는다** — 본인이 삭제했든 관리자가 삭제했든 같은 향수에 다시 쓸 수 있다. (이 항목은 명시적 답이 없어 사용자 확정 전의 가정이며, 다르게 정하면 이 ADR을 대체한다.)

## Consequences

- (+) 한 향수의 시향기 목록이 사람 수만큼 다양해지고, 도배·반복 작성으로 추천을 모으는 시도가 줄어든다.
- (+) 응답에 `my_review_slug`를 두면 화면이 서버를 한 번 더 부르지 않고도 분기한다.
- (−) 같은 향수에 대한 생각이 바뀐 사용자는 새 글이 아니라 기존 글을 수정하거나 삭제 후 재작성해야 한다.
- (−) **스키마 영향**: `post`에 (`user_id`, `perfume_id`) 중복 방지가 필요하다. 소프트 삭제 제외 조건이 붙으므로 단순 유니크 제약으로는 표현할 수 없다. 구현 방식(애플리케이션 검사, 생성 컬럼 등)은 6단계 ERD 보완과 9단계에서 정한다. 확정 문서(02·04·05·06) 반영은 별도 승인 후 진행한다.
- (−) 동시 요청으로 중복 2건이 생길 수 있다. 구현 단계에서 처리 방식을 정한다.
