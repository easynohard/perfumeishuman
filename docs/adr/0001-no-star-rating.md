# 0001. 별점 없이 추천 버튼만 사용

- Status: **Accepted** (2026-08-07 확정, 2026-08-09 소급 기록)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) §2 W5, [02-user-stories.md](../02-user-stories.md) C2

## Context

향수 리뷰 플랫폼의 표준은 5점 별점이다(프라그란티카, 커머스 리뷰 등). 그러나 이 서비스의 정체성은 시향기를 "평가 데이터"가 아니라 **"읽을거리"**로 만드는 것이다. 별점이 있으면 ① 시향기가 점수의 부속물이 되고, ② 향수 간 점수 경쟁이 생겨 "재미있게 소개한다"는 컨셉과 충돌하며, ③ 낮은 점수를 둘러싼 분쟁·조작 문제가 초기 운영 부담이 된다.

한편 콘텐츠 큐레이션(홈 피드 추천순 정렬)과 작성자 보상 루프(받은 추천 수 확인)를 위한 반응 신호는 필요하다.

## Decision

별점/평점 시스템을 만들지 않는다. 반응 신호는 **시향기 단위의 추천 버튼 하나**로 통일한다 (1인 1추천, 취소 가능, 본인 글 추천 불가). 추천 수는 피드 정렬(추천순)과 작성자 동기 부여(내 시향기의 총 추천 수)의 재료로 쓴다.

## 검토한 대안

- **5점 별점**: 업계 표준이고 데이터 축적에 유리하나, 위 Context의 정체성 충돌로 기각.
- **다중 반응(이모지 등)**: 재미 요소는 있으나 MVP에서 큐레이션 신호가 분산되고 구현·UI 복잡도가 늘어 보류. 추후 별도 ADR로 재검토 가능.

## Consequences

- (+) 시향기가 콘텐츠로서의 성격을 유지하고, 점수 분쟁·조작 대응 부담이 사라진다.
- (+) 데이터 모델이 단순해진다 (평점 테이블 불필요, 추천만 존재).
- (−) "이 향수 몇 점이야?"라는 정량 정보를 원하는 사용자의 니즈는 충족하지 못한다.
- (−) 향수 간 정량 비교 기능(평균 평점 정렬 등)을 만들 수 없다 — 추천 수 기반 정렬로 대체.
- 이 결정은 서비스 정체성에 관한 것이므로, 뒤집으려면 새 ADR로 명시적 논의가 필요하다 (01 문서 W5 주석).
