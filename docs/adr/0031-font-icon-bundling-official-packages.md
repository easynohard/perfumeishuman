# 0031. 서체는 Pretendard 공식 동적 서브셋 패키지를 같은 출처에서 제공하고, 아이콘은 lucide-react로 쓰는 것만 포함한다

- Status: **Accepted** (2026-11-17 — 9단계 기술 스택 6번 결정, 사용자 승인)
- 대체 범위: [ADR 0025](./0025-typeface-and-icon-set.md) Decision 2의 **"SVG 스프라이트로 번들"** 부분만 대체한다. 서체·아이콘 선택(Pretendard·Lucide), 셀프 호스팅, 라이선스 고지는 0025 그대로다.
- 관련 문서: [ADR 0025](./0025-typeface-and-icon-set.md) · [ADR 0026](./0026-nextjs-typescript-single-codebase.md)(Next.js) · [ADR 0027](./0027-hosting-vercel-db-supabase-seoul.md)(Vercel) · [08-ui-design.md](../08-ui-design.md) §2·§3·§8·§10 · [quality/license-audit.md](../quality/license-audit.md) §2

## Context

ADR 0025는 서체 Pretendard Variable(OFL 1.1)을 셀프 호스팅(woff2 동적 서브셋)하고, 아이콘 Lucide(ISC)는 필요한 것만 SVG 스프라이트로 번들한다고 정했다. 실제 번들·서브셋 구성은 9단계로 넘겼다(08 §10).

- 한글 가변 서체 전체 파일은 약 2MB라 통째로 받으면 01 N5(FCP 2.5초)를 위협한다.
- 시향기는 이용자가 자유롭게 쓰므로 어떤 글자가 나올지 미리 알 수 없다.
- 운영자는 1인·첫 개발이다. 별도 빌드 도구(서브셋 생성기, 스프라이트 생성 스크립트)를 배우는 것을 비용으로 본다.
- 라이선스 감사 1차(§2.2)는 스타일 가이드의 SVG 경로가 Lucide 원본을 손으로 옮긴 것이므로, 구현 시 패키지에서 직접 가져와 출처를 추적 가능하게 하라고 지적했다.

## Decision

### 1. 서체 — `pretendard` npm 패키지의 동적 서브셋 버전

- npm `pretendard` 패키지를 설치하고, 제작자가 배포하는 **Pretendard Variable 동적 서브셋 CSS**(글자 범위별로 나뉜 woff2 조각 + `unicode-range` 안내)를 앱 최상위 레이아웃에서 불러온다.
- 조각 파일은 **우리 사이트(Vercel)와 같은 출처**에서 제공한다. 외부 서체 CDN을 쓰지 않는다(0025 원칙 유지).
- 브라우저는 화면에 실제로 나오는 글자가 든 조각만 받는다. 이용자가 쓴 어떤 글자도 빠지지 않는다.
- `font-display: swap`(폴백 서체로 먼저 보여 준 뒤 교체)을 유지한다. 서체 파일은 내용이 바뀌지 않으므로 **장기 캐시(1년, immutable)** 로 제공한다.
- `preload` 대상 조각과 폴백 서체 크기 보정 등 세부 튜닝은 구현 단계에서 Lighthouse로 측정하며 정한다.

### 2. 아이콘 — `lucide-react` 패키지, 쓰는 것만 포함

- npm `lucide-react` 패키지를 설치하고, 화면 코드에서 **이름으로 불러온 아이콘만** 결과물에 포함한다(쓰지 않는 아이콘은 빌드 시 자동 제외).
- 아이콘은 인라인 SVG로 그려지므로 별도 요청이 없다. 08의 규격(24px 격자, 선 두께 1.75, `currentColor`)은 공통 속성으로 맞춘다.
- 스타일 가이드에서 손으로 옮긴 SVG 경로는 구현에서 쓰지 않는다(감사 1차 지적 해소).

### 3. 버전·고지

- 두 패키지 모두 버전을 고정(lock 파일)한다. 라이선스 고지(OFL 전문·ISC)는 0025 Decision 4대로 게시하며, 의존성 라이선스 정책은 9단계 ⑧에서 함께 다룬다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 서체 전체 파일 1개(가변 woff2) | 약 2MB로 첫 화면이 느려진다 |
| 자주 쓰는 글자만 직접 서브셋 생성 | 더 가볍지만 이용자 글의 드문 글자가 빠져 폴백 서체로 섞여 보인다. 생성 도구를 따로 배워야 한다 |
| Next.js `next/font/local`로 서체 제공 | 단일 파일에는 편리하지만 조각 파일 수십 개의 `unicode-range` 구성을 그대로 옮기기 번거롭다. 공식 CSS를 그대로 쓰는 편이 단순하다 |
| 아이콘 SVG 스프라이트(0025 원안) | 목적(필요한 것만·외부 호출 없음)은 같지만 스프라이트 생성 스크립트와 참조 관리가 추가된다. `lucide-react`가 같은 결과를 설정 없이 낸다 |

## Consequences

- (+) 명령어 두 줄(패키지 설치)과 코드 몇 줄로 끝나 학습 부담이 가장 작다.
- (+) 외부 호출이 없어 0025·ADR 0010의 개인정보 취지를 지킨다. 같은 출처라 연결 비용도 없다.
- (+) 아이콘 출처가 패키지로 추적되어 라이선스 감사가 단순해진다.
- (−) 동적 서브셋은 화면에 따라 조각 여러 개를 받는다. 첫 방문 시 요청 수가 늘 수 있어 구현 단계에서 FCP를 측정한다.
- (−) 인라인 SVG는 아이콘이 많은 화면에서 HTML이 약간 커진다. 이 서비스의 아이콘 수(수십 개)에서는 무시할 수준이다.
- 08 §10의 "서체·아이콘 파일의 실제 번들·서브셋 구성 — 9단계" 항목은 이 ADR로 닫는다.
