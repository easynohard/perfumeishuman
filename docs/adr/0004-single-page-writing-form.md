# 0004. 시향기 작성 폼은 한 페이지 스크롤 + 100자 숏폼

- Status: **Accepted** (2026-08-07 확정, 2026-08-09 소급 기록)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) §2 M5, §3 N3, [02-user-stories.md](../02-user-stories.md) D1·B1

## Context

작성 경험은 이 서비스의 심장이다. 빈 텍스트박스는 "글쓰기 과제"처럼 느껴져 이탈을 만들고, 반대로 여러 스텝의 위저드는 진행 부담(남은 단계에 대한 피로)을 만든다. 목표는 "재미있는 답변 놀이"(N3) — 로그인 벽을 넘어온 사용자가 끝까지 완주하게 하는 것이다.

또한 홈 피드가 서비스의 첫인상인데, 긴 글은 카드에서 잘려 매력이 전달되지 않는다.

## Decision

- 작성 폼은 **스텝 이동 없는 한 페이지 스크롤**로 한다. 상단에 자유 서술, 아래로 스크롤하면 태그 질문 4종.
- 자유 서술은 **"이 향수가 사람이라면, 어떤 사람인지 소개해 주세요" 프롬프트에 최대 100자** — 숏폼으로 강제해 작성 부담을 낮추고, 피드 카드에 전문이 그대로 노출되게 한다.
- 별도의 한 줄 요약(제목) 필드는 두지 않는다 — 100자 서술 자체가 제목 역할.
- 태그 질문 4종(나이대/분위기/만나는 상황/어울리는 사람)은 각 최소 1개 필수, 탭만으로 응답.
- 막힐 때를 위한 "질문 카드" 버튼(랜덤 유도 질문)과 회전 예시 placeholder를 제공한다.
- 작성 중 내용은 자동 임시저장한다 (로그인 이탈 후 복귀 대비).

## 검토한 대안

- **멀티스텝 위저드**: 한 번에 하나씩 물어 집중시키는 장점이 있으나, 남은 단계에 대한 피로와 이탈 지점 증가로 기각 (2026-08-07 사용자 피드백으로 한 페이지화 확정).
- **자유 서술 장문 허용(제한 없음)**: 표현의 깊이는 얻지만 작성 부담이 커지고 피드 카드에서 잘리며, "짧고 재미있는 소개"라는 콘텐츠 정체성과 어긋나 기각.
- **한 줄 요약(제목) + 본문 구조**: 통상적인 게시글 구조이나 입력 필드가 하나 늘어 부담이 커지고, 100자 숏폼이 제목을 겸할 수 있어 제거 (2026-08-07 확정).

## Consequences

- (+) 작성 완주율(전환율)에 유리하고, 모든 시향기가 피드 카드에 전문 노출되는 균질한 숏폼 콘텐츠가 된다.
- (+) 화면 설계·데이터 모델이 단순해진다 (본문 1필드 + 태그 관계).
- (−) 100자로는 향의 변화(탑→베이스) 같은 깊은 서술이 불가능하다 — 깊이를 원하는 작성자의 니즈는 포기. 수요가 확인되면 "더 소개하기" 같은 선택 확장 필드를 새 ADR로 검토.
- (−) 자동 임시저장, 회전 placeholder, 질문 카드 풀(초기 20~30개 질문) 등 구현·콘텐츠 준비 항목이 늘어난다.
