# 0024. 색상 체계는 흰색·코발트 블루·검정으로 제한한다

- Status: **Accepted** (색상 방향 — 사용자 지정, 2026-11-12). 세부 값·규칙(§Decision 1~6)은 위임받아 작성한 초안이며 8단계 승인 때 함께 확정한다
- 관련 문서: [08-ui-design.md](../08-ui-design.md) §2.1·§2.6, [ADR 0001](./0001-no-star-rating.md)

## Context

8단계 UI 디자인 착수 시 사용자가 "하얀 배경에 코발트 블루, 검정색"을 지정했다. 시연 데모(`ppt/index.html`)는 남색 포인트(`#002FA5`) 위에 장미색(추천·작성)과 금색(관리자)을 더한 3색 구조였다. 지정된 팔레트로는 장미색·금색을 쓸 수 없어, 추천·작성·관리자·오류의 시각 구분을 새로 정해야 한다. WCAG AA(1단계 N10)도 만족해야 한다.

## Decision

1. 유채색은 **코발트 `#0047AB`** 하나, 바탕은 **흰색 `#FFFFFF`**, 글자·강조 중립은 **검정 `#0A0A0A`**. 보조로 순수 무채색 회색 3단(`#595959` 보조 글자, `#767676` 조작 요소 경계, `#E4E4E7` 장식 구분선)과 코발트 연한 틴트 `#EEF3FC`만 쓴다.
2. 역할 분담: 코발트 = 누를 수 있음·선택·추천·링크, 검정 = 읽을 내용·되돌리기 어려운 확정 행동·관리자 영역·토스트.
3. 시연 데모의 장미(추천·작성) → 코발트, 금(관리자) → 검정으로 대체한다.
4. **위험·오류·성공에 별도 색을 두지 않는다.** 아이콘 + 문구 + 굵기 + 검정 테두리로 구분한다.
5. 코발트 바탕 위에는 흰 글자만, 검정 바탕 위에는 코발트 글자를 쓰지 않는다(대비 2.4 : 1).
6. 다크 모드는 MVP에서 제공하지 않는다(`color-scheme: light`).

대비(흰 바탕 기준): 검정 19.8, 코발트 8.4, 코발트 진한 `#003580` 11.5, 보조 글자 7.0, 조작 경계 4.5 : 1 — 텍스트·비텍스트 모두 AA 이상.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 오류 전용 빨강 1색 추가 | 지정 팔레트 이탈. 아이콘·문구로 대체 가능하고, 오류 인지가 약하다는 근거가 생기면 그때 대체 ADR로 도입 |
| 시연 데모의 남색(`#002FA5`) 유지 | 코발트 블루(`#0047AB`)가 더 밝고 "코발트"라는 지정에 부합. 대비는 둘 다 충분 |
| 회색 대신 코발트 계열 중립색 | 유채색이 둘로 느껴지고 코발트 포인트가 흐려진다 |

## Consequences

- (+) 색 규칙이 단순해 구현·유지 비용이 낮고, 글(주인공)이 도드라진다.
- (+) 색 토큰이 8개 안팎이라 CSS가 작다(N5).
- (−) 오류·위험이 색으로 즉시 읽히지 않는다. 아이콘·문구·굵기에 의존하므로 컴포넌트마다 §2.6 규칙을 지켜야 한다.
- (−) 코발트가 "링크·선택·추천·주 버튼"에 모두 쓰여, 화면에 코발트 요소가 겹치지 않게 배치에 주의가 필요하다(화면당 Primary 1개).
- 라이선스: 색상 값 자체는 별도 라이선스 대상이 아니다(08 라이선스 감사 §색상).
