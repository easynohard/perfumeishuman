# 0018. 목록 페이지 크기 — 사용자·관리자 모두 기본 10개

- Status: **Accepted** (2026-10-28 확정)
- 보완 대상: [0017-api-design-principles.md](./0017-api-design-principles.md) §5 (기본 페이지 크기 20 → 10). 그 외 0017의 결정(오프셋 방식 등)은 그대로 유효하다
- 관련 문서: [04-wireframes.md](../04-wireframes.md) §1.3·§6-10, [07-api-spec.md](../07-api-spec.md) §1.6

## Context

ADR 0017은 모든 목록 API의 기본 `size`를 20으로 정했다. 반면 4단계 와이어프레임(§1.3, 확정 10)은 시향기 카드가 나오는 모든 목록을 **"10개씩 + [더보기]"** 로 확정했다. 두 결정이 충돌해, 프론트가 항상 `size=10`을 명시하지 않으면 화면 명세와 다른 개수가 내려온다. 07 §2 초안을 만들며 발견했다.

## Decision

1. 페이지를 나누는 모든 목록 API의 기본 `size`는 **10**이다. 사용자 화면(시향기 카드 목록, 향수 행 목록, 검색 결과)과 **관리자 목록(시향기·카탈로그·신고)** 모두 같다.
2. 한 화면에 전부 보여주는 목록 — 브랜드 목록(`/brands`)과 계열 목록(`/accords`) — 은 페이지네이션을 적용하지 않는다. 가나다 섹션·고정 순서 그리드가 한 번에 보여야 하는 화면이다.
3. 페이지 방식(오프셋, `page` 1부터)과 응답 형식은 ADR 0017 그대로다. `size` 상한은 구현 단계에서 정한다.

## 검토한 대안

- **기본 20 유지 + 프론트가 항상 `size=10` 명시**: 호출 하나라도 누락되면 화면 명세와 달라지고, 기본값이 사실상 쓰이지 않는 값이 된다. 기각.
- **사용자 10 / 관리자 20으로 분리**: 관리자는 한 화면에서 많이 훑는 편이 효율적이지만, 규칙을 하나로 유지하는 쪽을 사용자가 택했다.

## Consequences

- (+) 화면 명세(10개씩 + 더보기)와 API 기본값이 일치한다.
- (+) 목록 종류에 따라 기본값을 외울 필요가 없다.
- (−) 관리자 목록은 한 번에 보이는 행이 적어 페이지 이동이 잦다. 관리자 목록의 "N페이지로 이동"(07 §1.6)으로 보완한다. 운영하면서 불편하면 관리자 목록 기본값만 올리는 새 ADR을 쓴다.
- (−) `/brands`·`/accords`는 전체 목록을 한 번에 내려준다. 브랜드 수가 크게 늘면 재검토가 필요하다.
