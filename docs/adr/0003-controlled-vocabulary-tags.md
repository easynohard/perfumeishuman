# 0003. 태그·계열은 관리자 지정 통제 어휘 사용

- Status: **Accepted** (2026-08-07 확정, 2026-08-09 소급 기록)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) §2 S1, [02-user-stories.md](../02-user-stories.md) A3·D1

## Context

태그는 두 곳에서 쓰인다: ① 향수의 계열(시트러스, 플로럴, 우디, 머스크 등) — 입문자의 탐색 경로, ② 시향기 작성 폼의 프로필 질문(나이대/분위기/상황/어울리는 사람) — 탭만으로 답하는 선택지.

자유 태그를 허용하면 표기 변형(시트러스/citrus/씨트러스), 오타, 스팸 태그가 쌓여 탐색·필터 품질이 무너지고, 이를 정리하는 운영 비용이 1인 운영 규모를 넘는다. 또한 작성 폼의 "탭만으로 답한다"는 설계는 선택지가 고정되어 있어야 성립한다.

## Decision

- 향수의 **계열**은 관리자가 향수 데이터에 지정한 값만 사용한다. 사용자 자유 태그는 받지 않는다.
- 시향기의 **프로필 태그**(나이대/분위기 키워드/만나는 상황/어울리는 사람)는 사전에 정의된 선택지에서 고르는 방식으로 한다. 자유 입력 없음.
- 태그 선택지의 최종 세트는 4단계 와이어프레임에서 화면과 함께 확정한다 (02 문서 미해결 질문 1).

## 검토한 대안

- **자유 태그**: 표현의 다양성은 얻지만 표기 변형·스팸 정리 비용이 크고, 필터·탐색 UI가 예측 불가능해져 기각. 자유로운 표현은 태그가 아니라 100자 자유 서술이 담당한다.
- **자유 태그 + 관리자 승인(하이브리드)**: 승인 큐 운영 부담으로 MVP에서 보류. 태그 수요가 확인되면 새 ADR로 재검토.

## Consequences

- (+) 탐색·필터 UI가 안정적이고, 태그 정리 운영 비용이 없다. 데이터 모델도 단순해진다 (선택지 테이블 + 다대다 관계).
- (+) 통제 어휘이므로 추후 동의어 매핑(예: "아저씨" → 30~40대+남성 이미지) 같은 검색 고도화의 기반이 된다.
- (−) 사용자가 원하는 표현이 선택지에 없을 수 있다 → 선택지 세트의 품질이 중요해지며, 운영하며 선택지를 추가·개정할 관리 절차가 필요하다.
- (−) 선택지 개정 시 기존 시향기와의 정합성(없어진 선택지 처리 등)을 6단계 ERD에서 고려해야 한다.
