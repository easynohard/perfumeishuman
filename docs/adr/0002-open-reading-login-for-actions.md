# 0002. 열람은 비로그인 개방, 작성·추천은 소셜 로그인 필수

- Status: **Accepted** (2026-08-07 확정, 2026-08-09 소급 기록)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) §2 M3·M4·M6·W6, §3 N2·N4·N6, §4.2, [02-user-stories.md](../02-user-stories.md) C1·C2

## Context

서비스 성장의 주 유입 경로는 검색엔진(SEO)과 공유 링크다. 열람에 로그인 벽이 있으면 이 경로가 막힌다. 반면 추천 수는 홈 피드 큐레이션의 재료이므로, 비로그인 추천을 허용하면 추천 수 부풀리기 등 조작에 취약해져 서비스 품질(신뢰) 자체가 훼손된다. 작성 역시 책임 소재(본인 글 수정/삭제, 악성 글 대응)를 위해 계정이 필요하다.

이메일/비밀번호 가입은 1인 개발 운영에서 비밀번호 관리·복구 부담이 크고, 가입 절차가 길수록 작성 전환율이 떨어진다.

## Decision

- **열람**: 모든 콘텐츠를 비로그인으로 개방한다. 열람 경로에는 어떤 로그인 벽도 두지 않으며, 시향기·향수·브랜드 페이지는 서버 렌더링으로 SEO에 노출한다.
- **작성·추천**: 소셜 로그인(공급자 1개로 시작, 카카오 우선) 사용자만 가능. 1인 1추천, 이메일/비밀번호 가입은 만들지 않는다.
- **전환 장치**: 게스트가 추천/작성을 시도하는 순간에만 로그인을 유도하고, 로그인 완료 시 직전 행동(추천 반영, 작성 화면 복귀)으로 이어지게 한다.

## 검토한 대안

- **비로그인 추천 허용**: 참여 장벽은 낮아지나 조작 위험이 이익보다 크다고 판단해 기각 (01 문서 §4.2에서 확정). 대신 추천 버튼을 로그인 전환 장치로 활용.
- **이메일/비밀번호 가입 병행**: 소셜 계정이 없는 사용자를 포용하나, 운영 부담과 가입 이탈 증가로 기각.

## Consequences

- (+) SEO·공유 기반 성장 경로가 열리고, 추천 수의 신뢰가 큐레이션 품질을 보장한다.
- (+) 인증 구현이 단순해진다 (비밀번호 저장·복구 플로우 없음).
- (−) 소셜 로그인 공급자에 대한 외부 의존이 생긴다 (장애 시 작성·추천 불가).
- (−) 로그인이라는 벽이 작성 전환율의 최대 리스크로 남는다 → 로그인→작성 전환율을 핵심 지표로 추적하고(N3), 작성 중 내용 보존 등 이탈 최소화 UX가 필수가 된다.
