# 0021. 관리자 전용 신고 API는 내부 id를 식별자로 쓴다 (0017의 예외)

- Status: **Accepted** (2026-10-28 확정)
- 보완 대상: [0017-api-design-principles.md](./0017-api-design-principles.md) §1 "내부 순차 id는 노출하지 않는다"
- 관련 문서: [07-api-spec.md](../07-api-spec.md) §2, [06-erd.md](../06-erd.md) (`report`)

## Context

ADR 0017은 슬러그·랜덤 코드만 쓰고 내부 순차 id는 요청·응답에 노출하지 않기로 했다. 그런데 신고(`report`)에는 공개 코드가 정해져 있지 않고 정수 `id`만 있다. 신고는 관리자 신고 관리 화면(`/admin/reports`)에서만 조회·처리된다.

## Decision

`/admin/reports/{id}`는 **신고의 내부 정수 id**를 식별자로 쓴다. 이는 ADR 0017 §1의 **유일한 예외**다.

- 이 id는 **관리자 API 응답에만** 나타난다. 일반 사용자 API·공개 화면 URL에는 나오지 않는다.
- 접근은 매 요청마다 관리자 권한을 검사해 보호한다(07 §1.4).
- 신고자 정보(닉네임·공개 코드)도 같은 응답에만 담긴다.
- 다른 관리자 API(시향기·향수·브랜드)는 계속 슬러그를 쓴다.

## 검토한 대안

- **신고에 랜덤 공개 코드 추가**: 0017과 일관되지만 `report` 컬럼·생성·충돌 검사 로직이 늘어나고, 관리자만 쓰는 값이라 얻는 이득이 작다. 사용자가 관리자 전용이므로 예외를 두기로 해서 기각.

## Consequences

- (+) `report` 스키마와 생성 로직이 늘지 않는다.
- (−) 신고 건수와 순서가 id로 추정될 수 있으나, 관리자만 볼 수 있어 문제가 되지 않는다. 신고 API를 일반 회원에게 열게 되면 이 ADR을 대체하는 새 ADR이 필요하다.
