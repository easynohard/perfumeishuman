# 0026. 화면과 API를 Next.js + TypeScript 한 코드베이스로 만든다

- Status: **Accepted** (2026-11-16 — 9단계 기술 스택 1번 결정, 사용자 승인)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) N5·N6·N8·N11, [07-api-spec.md](../07-api-spec.md) §1, [ADR 0017](./0017-api-design-principles.md)

## Context

9단계 기술 스택의 첫 결정이다. 개발·운영은 **1인**이고, 운영자는 **프로그래밍 언어·프레임워크를 처음 다룬다**. 이미 확정된 조건은 다음과 같다.

- 시향기·향수·브랜드 페이지의 **서버 렌더링**(N6 SEO)과 모바일 3G FCP 2.5초(N5)
- 서버 관리 최소화(N8), **serverless 우선 검토**·개인정보 국내 리전·비용 최소화(ADR 0017의 9단계 제약)
- REST + `/api/v1/` 접두사 + 세션 쿠키 인증(ADR 0017, 07 명세)
- 탭 전환·추천 ♥·작성 폼 임시저장처럼 화면 반응이 많은 UI(04·08)
- 표준적인 기술 선택으로 과정 자체를 보여줄 것(N11)

## Decision

1. **언어는 TypeScript**, **프레임워크는 Next.js**로 한다.
2. **화면(SSR 페이지)과 API(`/api/v1/...`)를 하나의 Next.js 프로젝트**에 둔다. 07 명세의 경로·요청·응답 형식은 그대로 유지한다. 프레임워크가 바뀌어도 API 계약(07 yaml)은 바뀌지 않는다.
3. 화면 개발은 기존 목 서버(`mock/`, 07 yaml 기반 Prism)로 먼저 진행하고 API 구현을 나중에 붙일 수 있게 한다.
4. 다음은 이 ADR에서 정하지 않는다. 각각 후속 결정에서 정한다.
   - 구체 버전·라우팅 방식(App Router/Pages Router)·사용할 기능 범위 → 10단계 컨벤션
   - 호스팅·DB(서울 리전) → 9단계 2번
   - 소셜 로그인·세션·CSRF 구현 라이브러리 → 9단계 3번
   - CSS 방식(08 디자인 토큰 → 변수/유틸리티) → 9단계 6번 또는 10단계

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| React(SPA) + Spring Boot(Java) 분리 | 언어 2개·코드베이스 2개로 1인 초보에게 학습·운영 부담이 두 배다. JVM은 serverless에서 시작이 느리고 무겁다(ADR 0017 제약과 어긋남). SPA는 SEO(N6)용 서버 렌더링을 따로 갖춰야 한다. 국내 채용 시장 친화성은 장점으로 인정 |
| Django(Python) | 서버 템플릿 렌더링·내장 관리자 화면은 강점이다. 하지만 탭·♥·임시저장 같은 화면 반응에 JavaScript를 따로 써야 해 결국 언어가 2개가 되고, serverless 배포 사례가 상대적으로 적다 |
| SvelteKit 등 다른 풀스택 프레임워크 | 구조는 비슷하게 맞지만 학습 자료·라이브러리·질문 답변의 양이 Next.js보다 적어 초보 1인에게 불리하다 |
| JavaScript(타입 없음) | 실수를 실행 전에 잡지 못한다. 품질 트랙의 타입 체크 CI 게이트가 TypeScript를 전제로 한다 |

## Consequences

- (+) 배울 언어가 하나이고, 화면과 API를 한 저장소·한 배포로 관리한다(N8).
- (+) 서버 렌더링(N6)·serverless 배포(ADR 0017)를 프레임워크 기본 기능으로 충족한다.
- (+) 학습 자료와 생태계가 커서 막혔을 때 해결 경로가 많다. 포트폴리오로도 표준적이다(N11).
- (−) React 개념(컴포넌트·상태)을 함께 배워야 한다. 기능이 많아 처음에는 쓸 기능을 좁혀야 한다 — 10단계 컨벤션에서 범위를 정한다.
- (−) 프레임워크의 주요 버전 변경이 잦은 편이라 업그레이드 비용이 생긴다. 버전 고정과 업그레이드 주기는 10단계에서 정한다.
- (−) 화면과 API가 한 프로젝트에 있어 API 코드가 화면 코드에 섞이지 않도록 디렉토리 경계를 정해야 한다(10단계).
- Next.js(MIT)와 TypeScript(Apache-2.0)는 허용형 라이선스다. 의존성 전체 정책은 9단계 8번(라이선스 2차 감사)에서 정한다.
