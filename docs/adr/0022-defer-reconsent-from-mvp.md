# 0022. 약관 개정 시 재동의는 MVP에서 제외하고, 향후 도입 설계안을 보존한다

- Status: **Accepted** (2026-10-28 확정) — [0020](./0020-reconsent-on-policy-revision.md)을 대체한다
- 관련 문서: [0010-minimal-personal-data-collection.md](./0010-minimal-personal-data-collection.md), [02-user-stories.md](../02-user-stories.md) F1·F2, [06-erd.md](../06-erd.md) (`confirmhistory`·`policyversion`), [07-api-spec.md](../07-api-spec.md) §2

## Context

ADR 0020은 약관·처리방침 개정 시 기존 회원에게 재동의를 받고, 거부하면 탈퇴를 안내하기로 했다. 이후 사용자가 **MVP 범위에서는 재동의를 빼고, 나중에 도입할 수 있도록 설계만 남기기로** 했다. MVP 출시 전에는 약관이 개정될 일이 없고, 재동의 모달은 화면·API·상태 처리를 늘리며 쓰기 전환율(N2·N3)에도 마찰을 더한다.

## Decision

1. **MVP에는 재동의 절차를 구현하지 않는다.** 동의는 가입 시 1회(02 F1)이며 동의 이력(`confirmhistory`)에 기록된다.
2. 약관·처리방침이 개정되면 **서비스 내 게시**로 공지하고(이메일을 수집하지 않으므로 — ADR 0010), 시행일 전에 게시하며, 이전 버전을 열람할 수 있게 한다(02 F2). 시행일 이후 계속 이용하는 회원에 대한 취급은 **8단계 약관 조문에서 명시**한다.
3. **중대한 개정**(수집 항목 추가·이용 목적 변경 등)이 생기거나 **수익화(W1)를 도입**할 때는 이 ADR을 재검토하고 재동의 도입 여부를 다시 판단한다. 법적 요건은 구현 전에 확인한다.
4. 도입을 어렵게 만들지 않도록, 현재 스키마·API가 이미 갖춘 것을 유지한다.
   - `confirmhistory`는 (사용자, 약관 버전, 처리방침 버전, 동의 시각, 동의 경로) 행을 **추가하는 구조**라 재동의 이력을 같은 테이블에 쌓을 수 있다.
   - `policyversion`이 버전·시행일을 갖는다.

## 향후 도입 시 설계안 (ADR 0020에서 이어받음)

도입하기로 결정하면 아래를 구현한다. 모두 **MVP에는 없는 것**이다.

| 항목 | 내용 |
|---|---|
| 모달 | 시행 후 로그인 상태로 접속하면 재동의 모달. **화면 추가 없음**(화면 16개 유지). 새 버전 요지와 `/terms`·`/privacy` 링크 포함 |
| 동의 | `POST /me/consents`로 새 버전·시각을 `confirmhistory`에 추가 기록(동의 경로는 재동의로 구분, 기존 행 보존) |
| 상태 노출 | `GET /me` 응답의 `pending_consent`(없으면 `null`) |
| 거부 | 즉시 탈퇴시키지 않고 04 §4.2 탈퇴 확인 모달로 **탈퇴를 안내** |
| 미동의 중 제한 | 작성·추천·닉네임 변경 등 회원 기능 API는 403 `CONSENT_REQUIRED`, 열람은 가능 |
| 경미한 개정 구분 | 오탈자 수정까지 재동의를 받지 않으려면 `policyversion`에 "재동의 필요" 필드를 추가한다(ERD 변경 + 새 ADR) |
| 문서 | 04 §3에 재동의 모달 추가, 02 F2 AC 보강 |

## 검토한 대안

- **MVP부터 재동의 구현(ADR 0020)**: 동의 증빙이 버전별로 남지만, 출시 전에는 개정이 없어 당장 쓰이지 않는 기능을 먼저 만들게 된다. 기각.
- **재동의 없이 공지만 하고 설계안도 남기지 않음**: 나중에 도입하려 할 때 다시 설계해야 하고, 스키마·API에서 막히는 지점이 있는지 확인되지 않는다. 기각.

## Consequences

- (+) MVP의 화면·API·상태 처리가 줄고 가입 직후 마찰이 늘지 않는다.
- (+) 도입 시 변경 목록이 위 표에 정리돼 있고, 스키마 변경 없이 시작할 수 있다.
- (−) **출시 전 확인이 필요하다.** 개정 후 계속 이용을 동의로 볼 수 있는지, 개인정보 처리방침의 중대한 변경 시 별도 동의가 필요한지는 법무 확인 대상이다. 출시 전 관문(Launch Gate)의 약관·처리방침 최종 확정 시점에 함께 검토한다.
- (−) 약관 개정 시 기존 회원의 동의 증빙은 가입 시점 버전까지만 남는다.
