# 0008. 회원 탈퇴 시 시향기는 익명 처리 후 보존한다

- Status: **Accepted** (2026-08-16 확정)
- 관련 문서: [01-problem-definition-scope.md](../01-problem-definition-scope.md) M6·M8, [02-user-stories.md](../02-user-stories.md) C2·D3·D4, [03-sitemap-ia.md](../03-sitemap-ia.md) §3, [0002-open-reading-login-for-actions.md](./0002-open-reading-login-for-actions.md), `docs/legal/terms-of-service.md`

## Context

소셜 로그인으로 개인정보를 수집하는 이상 **동의 철회권(회원 탈퇴)** 은 MVP 필수 기능이다. 그런데 탈퇴자가 남긴 시향기를 함께 삭제하면 서비스의 자산이 소실된다.

- 시향기는 이 서비스의 콘텐츠 그 자체이며(M3), 추천순 피드(M7)와 향수 상세의 시향기 목록(M2)을 구성한다. 인기 글이 작성자 탈퇴로 사라지면 읽기 루프(FL1)에 구멍이 생긴다.
- SEO(N6)로 유입되는 URL(`/reviews/:slug`)이 죽는다. 검색 유입은 초기 성장의 주 채널이다.
- 탈퇴자가 다른 글에 눌렀던 추천까지 지우면, **아무 잘못 없는 다른 작성자의 받은 추천 수(M8)가 이유 없이 줄어든다.** 작성자 동기 부여 루프를 훼손한다.

한편 개인정보보호법상 탈퇴 시 개인정보는 파기해야 한다. 다만 **재식별이 불가능하게 익명 처리된 정보는 더 이상 개인정보가 아니므로** 보존이 가능하다. 이 경계를 정확히 지키는 것이 이 결정의 핵심이다.

데이터 모델(5단계)·ERD(6단계) 직전이며, 나중에 바꾸면 마이그레이션 비용이 발생하므로 지금 확정한다.

## Decision

**탈퇴 시 계정은 익명화하고, 시향기와 추천 이력은 그대로 보존한다.**

### 1. 익명 표시명

- 형식: `user_NNNNNN` (6자리 숫자)
- **원본 user id에서 유도하지 않는다.** 해시·순번·타임스탬프 기반 생성 금지 — 원본과 무관한 난수여야 익명화로 인정된다.
- 유니크 제약을 걸어 충돌을 방지한다. 이미 사용된 번호는 재사용하지 않는다.

### 2. 파기 대상 (즉시·복구 불가)

소셜 계정 식별자(공급자 고유 ID), 이메일, 기존 닉네임, 프로필 이미지, 로그인 이력 등 **개인을 식별할 수 있는 모든 값**을 파기한다. 결과적으로 재가입해도 과거 글과 연결할 수 없다 — **되돌릴 수 없는 조치**이며, 이 점을 탈퇴 확인 화면과 약관에 명시한다.

### 3. 보존 대상

| 대상 | 처리 |
|---|---|
| 작성한 시향기 | 본문·태그·작성일 그대로 유지. 작성자 표시만 `user_NNNNNN` |
| 받은 추천 수 | 유지 |
| 누른 추천 | 유지 — 레코드의 user 참조를 익명 계정으로 이관해 카운트를 보존하고, 1인 1추천 유니크 제약도 함께 유지 |
| 작성자 프로필 `/users/:id` | **비활성.** 시향기의 닉네임이 링크로 동작하지 않고 텍스트로만 표시된다 |

### 4. 권한

탈퇴자의 시향기는 본인 수정·삭제가 불가능해진다. 이후 수정·삭제는 **관리자만** 가능하다(M9, 사유 메모 기록).

### 5. 전제 조건 — 사전 고지·동의

가입 시 **"탈퇴해도 작성한 시향기는 익명 처리되어 서비스에 남습니다"** 를 명시적으로 알리고 동의를 받는다. 이 고지 없이는 사후 삭제 요구를 거절할 근거가 없다. 약관(`이용자 콘텐츠의 권리와 이용허락` 조항)에 이용허락의 존속을 함께 규정한다.

## 검토한 대안

- **시향기 함께 삭제**: 법적으로 가장 단순하지만 콘텐츠·SEO·읽기 루프 손실이 크고, 다른 작성자의 추천 수까지 흔들려 기각.
- **닉네임 유지한 채 계정만 비활성화**: 닉네임은 그 자체로 식별 가능성이 있어 익명화로 인정되기 어렵다. 개인정보 파기 의무 위반 소지가 있어 기각.
- **"탈퇴한 사용자"로 일괄 표시**: 구현은 가장 단순하나 여러 탈퇴자의 글이 한 사람처럼 보인다. 작성자 단위 구분이 사라져 같은 사람의 글인지 아닌지 독자가 오인한다. 난수 표시명이 이 문제를 비용 없이 해결하므로 기각.
- **프로필 페이지도 유지**: 익명 계정의 글을 모아 보여주면 작성 패턴이 누적되어 재식별 여지가 커진다. 프로필은 "재미있는 작성자를 따라 읽는" 기능(S2)인데 탈퇴자에겐 의미가 없어 기각.

## Consequences

- (+) 콘텐츠·SEO·추천 수가 탈퇴로 훼손되지 않는다. 읽기 루프(FL1)와 작성자 동기 부여 루프(M8)가 모두 보존된다.
- (+) 개인정보는 파기하고 콘텐츠는 남기는, 법적으로 방어 가능한 구조다.
- (+) 추천의 1인 1추천 제약(N4)이 탈퇴 후에도 유지되어 조작 방지 로직이 단순해진다.
- (−) ERD에 익명 계정 상태(`withdrawn` 플래그 또는 상태 컬럼), 익명 표시명 컬럼, 표시명 유니크 제약이 추가된다. 사용자 조회 로직 전반에서 탈퇴 여부 분기가 필요하다.
- (−) 가입 플로우에 동의 고지가 반드시 들어가야 한다 — 로그인 바텀시트(3단계)가 "소셜 1탭"에서 "1탭 + 동의 고지"로 무거워진다. 전환율(N3) 영향을 8단계 UI에서 최소화해야 한다.
- (−) 탈퇴는 되돌릴 수 없다. 실수로 탈퇴한 사용자의 글을 복구해 달라는 문의에 응할 수 없으므로, 탈퇴 확인 화면에서 경고를 강하게 노출해야 한다.
- (−) 난수 표시명은 익명이지만, 글의 내용 자체가 신원을 드러낼 수 있다는 한계는 남는다(작성자가 본문에 개인 정보를 쓴 경우). 이는 삭제 요청 시 관리자 개별 처리로 대응한다.
