# 0028. 로그인은 카카오 1개, 도구는 Better Auth, 세션은 DB 저장·활동 없으면 20분 만료

- Status: **Accepted** (2026-11-16 — 9단계 기술 스택 3번 결정, 사용자 승인)
- 관련 문서: [ADR 0010](./0010-minimal-personal-data-collection.md)(최소 수집) · [ADR 0017](./0017-api-design-principles.md)(세션 쿠키 인증) · [ADR 0026](./0026-nextjs-typescript-single-codebase.md) · [ADR 0027](./0027-hosting-vercel-db-supabase-seoul.md) · [01](../01-problem-definition-scope.md) M4·N2·N4 · [02](../02-user-stories.md) C1 · [07-api-spec.md](../07-api-spec.md) §1.3·§3.1·§4.3.2

## Context

07은 세션 쿠키 인증(ADR 0017)과 로그인 흐름(§3.1·§4.3.2)을 정했고, 다음을 9단계로 넘겼다(07 부록 A): 소셜 로그인 공급자 수, 세션 저장소·만료 시간, CSRF 방어의 구체 방식. 01 M4·02 C1은 "공급자 1개(카카오 우선)로 시작, 9단계에서 확정"이다.

제약:

- 소셜 로그인에서 **공급자 구분 + 공급자 회원번호만** 저장한다. 이메일·프로필 이미지를 받지 않고, 공급자가 닉네임을 넘겨도 저장하지 않는다(ADR 0010).
- 탈퇴·로그아웃 시 세션을 즉시 지울 수 있어야 한다(07 §1.3).
- 쓰기 요청은 CSRF 검증을 거치고 실패 시 `403 CSRF_INVALID`(07).

2026-11-16 확인 사항:

- 카카오 로그인은 회원번호와 닉네임이 기본 제공 항목이다. 이메일(`account_email`)은 비즈 앱만 받을 수 있다. 닉네임은 기본 설정상 필수 동의 항목이며, 끄는 공식 방법은 확인되지 않았다. 회원번호는 고유하고 탈퇴해도 바뀌지 않는다.
- Auth.js(옛 NextAuth)는 2025년 Better Auth 팀으로 이관됐고, 새 프로젝트에는 Better Auth를 권장한다. Better Auth는 카카오·네이버·구글을 기본 지원하고 DB 세션을 지원한다.
- Better Auth는 사용자마다 이메일을 필수로 요구한다. 공급자가 이메일을 주지 않으면 `email_not_found`로 실패한다. 공식 문서는 `mapProfileToUser`에서 공급자 고유 ID로 대체 값을 채우는 방법을 안내한다.

## Decision

1. **공급자는 카카오 1개**로 출시한다. 07의 `provider` 열거는 `kakao`만 남기는 것을 원칙으로 한다(07 개정은 별도 승인). 네이버·구글은 출시 후 추가할 수 있다. 추가할 때는 아래 "다계정" 문제를 다시 판단한다.
2. 카카오 동의 항목은 **기본 제공 항목만** 쓰고 이메일·프로필 사진은 요청하지 않는다. 카카오가 넘기는 닉네임은 **저장하지 않는다**(ADR 0010).
3. **인증 도구는 Better Auth**로 한다.
   - 이메일 필수 요구는 `mapProfileToUser`에서 카카오 회원번호 기반 **대체 값(실제 이메일 아님)** 으로 채운다. 이름 칸은 자동 생성 닉네임으로, 사진 칸은 비워 둔다.
   - Better Auth가 기본으로 저장하는 값(카카오 토큰 등) 중 ADR 0010에 비춰 불필요한 것은 저장하지 않도록 설정한다. 설정으로 막을 수 없으면 저장 항목과 보관 이유를 처리방침에 반영하거나 대안을 쓴다.
   - **10단계 개발 환경 세팅 직후 작은 시험(스파이크)** 으로 위 두 가지를 먼저 확인한다. 충족하지 못하면 **직접 구현**(OAuth 처리 + 자체 세션 표)으로 바꾸고 이 ADR을 대체한다.
4. **세션**
   - 저장 위치: Supabase PostgreSQL(서울)의 세션 표. 추가 서비스 없음.
   - 만료: **일반 회원·관리자 모두 마지막 활동부터 20분**(슬라이딩). 활동이 있을 때마다 만료 시각을 연장한다.
   - 로그아웃·탈퇴 시 해당 사용자의 세션을 즉시 삭제한다(07 §1.3·§3.4).
   - 쿠키: `HttpOnly`, `Secure`, `SameSite=Lax`.
5. **CSRF**: `SameSite=Lax` 쿠키에 더해, 상태를 바꾸는 요청(POST·PATCH·PUT·DELETE)은 **`Origin` 헤더가 서비스 출처와 일치하는지** 서버가 확인한다. 불일치·누락이면 `403 CSRF_INVALID`. Better Auth 자체 경로의 내장 검사와 별개로 `/api/v1/...`에도 같은 검사를 둔다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 공급자 3개(카카오·네이버·구글) 동시 출시 | 가입 시 셋 중 하나를 고르는 방식이라도, 이메일을 받지 않으므로(ADR 0010) **한 사람이 공급자별로 3개 계정을 만드는 것을 알아낼 방법이 없다.** 1인 1추천(N4)이 약해진다. 공급자별 앱 등록·네이버 검수 등 출시 준비도 3배가 된다. 사용자 판단으로 "일단 1개"로 결정 |
| Supabase Auth | 토큰(JWT) 방식이라 07의 "서버 세션 + 탈퇴 시 즉시 삭제" 설계와 다르다. 공급자 프로필 정보를 자체 테이블에 함께 보관할 가능성이 있어 ADR 0010 충족을 따로 검증해야 한다 |
| Auth.js | Better Auth로 이관되어 신규 프로젝트에는 Better Auth가 권장된다 |
| 직접 구현 | 데이터 통제는 가장 확실하지만, 처음 개발하는 1인에게 보안 코드를 직접 쓰는 위험이 크다. 스파이크 실패 시의 대안으로 남긴다 |
| 세션 30일(슬라이딩) | 재로그인 빈도가 낮아 N2(이탈 최소화)에 유리하다. 하지만 사용자가 보안을 우선해 20분을 선택했다 |
| 관리자만 짧게(60분), 회원은 길게 | 위와 같은 이유로 사용자가 둘 다 20분으로 통일했다 |

## Consequences

- (+) 개인정보는 카카오 회원번호와 공급자 구분만 남는다(ADR 0010 유지).
- (+) 세션이 서버 DB에 있어 로그아웃·탈퇴·강제 만료를 즉시 처리할 수 있다.
- (+) 20분 만료로 공용 기기에서 로그아웃을 잊었을 때의 위험이 작다.
- (−) **20분 동안 서버 요청이 없으면 로그인이 풀린다.** 작성 폼에서 글자를 입력하는 동안은 서버 요청이 없으므로 20분 넘게 쓰면 등록 시 `401 LOGIN_REQUIRED`가 난다. 쓰던 글은 브라우저 임시저장(04 확정)으로 보존되고, 재로그인 후 `return_to`로 작성 화면에 돌아와 복원된다(07 §4.3.2). 이 흐름은 구현 단계에서 반드시 테스트한다.
- (−) 다시 방문할 때마다 로그인 창을 자주 본다. 브라우저의 카카오 로그인이 살아 있으면 버튼 한 번으로 재로그인된다. 로그인→작성 전환율(N3)을 출시 후 지표로 지켜보고, 이탈이 크면 만료 시간을 재검토한다(새 ADR).
- (−) 활동마다 세션 만료 시각을 DB에 갱신하므로 쓰기 요청이 늘어난다. 초기 규모에서는 영향이 작다(9단계 ⑩ 비용 추정에 반영).
- (−) 카카오 로그인 동의 화면에 "닉네임 제공"이 표시된다. 받은 닉네임은 저장하지 않는다는 점을 처리방침에 명시한다.
- (−) Better Auth의 기본 표(사용자·세션·연결 계정)와 06 ERD의 `user` 표 이름·칸을 맞추는 작업이 필요할 수 있다. 범위는 10단계 스파이크에서 확인하고, ERD 변경이 필요하면 사용자 승인을 받는다.
- 후속 문서 작업: 07 `provider` 열거를 `kakao`로 줄이기, 02 C1·04 §3·08 로그인 시트의 "9단계에서 확정" 문구를 "카카오(ADR 0028)"로 정리하기 — 모두 확정 문서라 사용자 승인 후 반영.
