# 1단계: 문제 정의 + MoSCoW 범위표 + 비기능 원칙

> 프로젝트: **perfumeishuman — "향수가 사람이라면?(what if perfume is human?)"**
> 향수를 사람에 비유한 재미있는 시향기를 작성·공유·추천하는 커뮤니티 웹서비스
> 작성일: 2026-08-07 · 상태: **확정** (2026-08-07 사용자 승인)

---

## 1. 문제 정의

### 1.1 배경

- 향수는 **직접 시향해 보기 전에는 알 수 없는 제품**이다. 그러나 시향에는 매장 방문·시간·비용이 들고, 온라인 정보만으로 구매를 결정해야 하는 경우가 많다.
- 그 온라인 정보는 노트 피라미드, 부향률, 계열 같은 **전문 용어 중심**으로 유통된다. 입문자에게는 진입 장벽이고, 애호가에게도 "그래서 실제로 뿌리면 어떤 느낌인데?"라는 질문에 답을 주지 못한다.
- 기존 플랫폼(프라그란티카, 국내 커머스 리뷰 등)의 리뷰는 **정보 나열이거나 짧은 구매 후기**에 그쳐, 읽는 재미가 없다. 리뷰를 "읽으러" 오는 사람은 없다.
- 향은 언어화하기 어렵지만, **사람에 비유하면 누구나 즉시 이해할 수 있다.** "비 오는 날 도서관에서 만난, 말수 적은 30대 국문과 조교 같은 향" > "베티버 30%". 사람들이 향수를 고를 때 실제로 원하는 것은 스펙이 아니라 **"이 향수를 뿌린 나는 어떤 이미지의 사람이 되는가"**이기 때문이다.

### 1.2 해결하려는 문제 (Problem Statement)

> **직접 시향하지 않고는 "내가 추구하는 이미지"에 맞는 향수를 찾기 어렵고, 기존 리뷰는 딱딱한 스펙 나열이라 탐색 자체가 지루하고 어렵다.**

### 1.3 해결 가설 (Solution Hypothesis)

> **"향수가 사람이라면?"이라는 하나의 포맷으로 시향기를 쓰게 하면, ① 향이 "사람 이미지"로 번역되어 시향 없이도 내가 추구하는 이미지로 향수를 고를 수 있고, ② 그 시향기 자체가 읽는 재미가 있는 콘텐츠가 되어 탐색이 콘텐츠 소비처럼 즐거워지며, ③ 서로의 경험을 공유하고 추천하는 과정에서 커뮤니티가 형성된다.**

MVP에서 검증할 것:
- [ ] 시향기가 **읽는 재미**로 체류를 만드는가? (체류 시간, 시향기 열람 수, 세션당 페이지 뷰)
- [ ] "사람 비유" 포맷이 향수 선택에 실제로 **도움이 되는가**? (탐색→향수 상세→외부 검색/재방문 흐름)
- [ ] 로그인이라는 벽을 넘어서까지 **쓰고 싶어지는가**? (비로그인 방문자 → 로그인 → 작성 완료 전환율)

### 1.4 프로젝트의 목적 (운영자 관점)

이 프로젝트는 사용자 가치 외에 운영자의 두 가지 장기 목적을 갖는다. 범위·기술 결정 시 이 목적을 함께 고려한다.

1. **커뮤니티 → 수익화 기반**: 사람이 모이는 커뮤니티를 먼저 만들고, 이후 제휴 링크(제품 클릭 → 외부 사이트 이동)·광고 등으로 수익화한다. MVP에서는 수익화를 구현하지 않되 설계상 여지를 남긴다(W1, N12).
2. **포트폴리오**: 기획→설계→개발→운영·마케팅의 전 과정을 운영자의 마케팅/IT 인프라 역량 증명으로 활용한다(N11).

### 1.5 타겟 사용자

| 구분 | 설명 | 핵심 니즈 |
|---|---|---|
| 완전 입문자 | 향수를 처음 접하는 사람. 용어도, 뭘 사야 할지도 모름 | 시향 없이, 용어 없이 "내가 추구하는 이미지"의 향수를 찾고 싶다 |
| 시향기 작성자 | 향에 대한 감상을 많이 쓰고 표현하고 싶은 사람 | 내 시향기를 재미있게 쓰고, 공유하고, 추천받는 반응을 얻고 싶다 |

두 그룹은 **읽는 쪽과 쓰는 쪽으로 커뮤니티의 순환을 이룬다.** 입문자는 재미로 읽으며 향수를 고르고, 작성자는 반응(추천)을 동력으로 콘텐츠를 공급한다. 읽던 입문자가 쓰는 사람이 되는 전환이 커뮤니티 성장의 핵심 경로다.

### 1.6 핵심 사용자 경험 한 줄 정의

> "향수 이름을 검색했더니 '이 향수는 첫 출근날 긴장한 신입사원 같은 사람'이라는 시향기가 나와서, 웃으면서 다른 향수의 '사람'들까지 계속 구경하게 되는 서비스"

## 2. MoSCoW 범위표 (MVP 기준)

> 서비스 정의: **"향수가 사람이라면?"이라는 컨셉으로, 향수별·브랜드별로 재미있는 시향기를 작성·공유하고 추천하는 커뮤니티 웹서비스.**
> 이 프로젝트는 (a) 커뮤니티 형성 → 향후 수익화(제휴 링크·광고)의 기반, (b) 운영자의 마케팅/IT 인프라 역량 포트폴리오라는 두 가지 목적을 갖는다.

### Must Have — 이것 없으면 서비스가 아님

| # | 기능 | 이유 |
|---|---|---|
| M1 | 향수 탐색 (이름/브랜드 검색 + 브랜드별 목록) | 탐색의 시작점. "향수별·브랜드별" 구조가 서비스의 뼈대 |
| M2 | 향수 상세 페이지 (기본 정보 + 시향기 목록) | 콘텐츠가 모이는 단위 |
| M3 | 시향기 열람 (비로그인 가능) | 방문자는 로그인 없이 모든 글을 읽을 수 있다. 진입 장벽 0 |
| M4 | 소셜 로그인 | 작성·추천의 전제. 카카오/구글 중 1개 공급자로 시작 |
| M5 | 시향기 작성 + **"향수가 사람이라면?" 작성 가이드** | 컨셉의 핵심. 빈 텍스트박스가 아니라 유도 질문 기반 폼: "이 향수가 사람이라면 어떤 사람인가요?", "누구에게 잘 어울릴까요?(20/30/40대 등 선택지)" 등. 자유 서술만으로는 재미있는 글이 나오지 않는다 |
| M6 | 시향기 추천 (로그인 사용자, 1인 1추천) | "재미"를 측정하는 신호이자 큐레이션 재료. 로그인 기반으로 조작 방지 |
| M7 | 홈 피드 (추천순/최신순 시향기) | 목적 없는 방문자도 바로 읽을거리를 만나게 함 |
| M8 | 내 시향기 모아보기 + 받은 추천 수 확인 | 작성자 동기 부여 루프. "쓰는 재미"의 보상 장치 |
| M9 | 관리자: 전체 게시물 CRUD (특히 수정·삭제) | 악의적인 글·거짓 정보 대응의 최소선. MVP에선 신고보다 관리자 직접 처리가 우선 |
| M10 | 모바일 우선 반응형 UI | 사용자 요구사항 |

### Should Have — 중요하지만 MVP 출시를 막지는 않음

| # | 기능 | 이유 |
|---|---|---|
| S1 | 계열/태그 기반 탐색 (시트러스, 머스크 등) | 이름을 모르는 완전 입문자의 탐색 경로 |
| S2 | 작성자 공개 프로필 (그 사람의 시향기 모음) | 재미있는 작성자를 따라 읽는 경험. M8의 공개 버전 |
| S3 | 시향기 신고 기능 | 커뮤니티 자정 장치. 초기엔 관리자 수동 대응(M9)과 병행 |
| S4 | 관리자: 향수/브랜드 데이터 관리 화면 | 초기엔 DB 직접 입력으로 대체 가능하나 운영 효율상 조기 필요 |

### Could Have — 여유가 되면

| # | 기능 | 이유 |
|---|---|---|
| C1 | 위시리스트/보유 목록 | 개인화 시작점, MVP 검증에는 불필요 |
| C2 | 시향기 본문 검색 | "비 오는 날" 같은 표현으로 역검색 — 재미있지만 후순위 |
| C3 | 향수 데이터 제보/등록 요청 | DB에 없는 향수 대응 |
| C4 | 관리자: 광고 슬롯/배너·디자인 요소 관리 | 수익화 대비. MVP 단계에선 코드 수정으로 대체 가능 |

### Won't Have (이번 MVP에서는 안 함)

| # | 기능 | 이유 |
|---|---|---|
| W1 | 수익화 (제휴 링크, 유료 광고, 제품 판매) | "많은 사람이 모이는 커뮤니티가 먼저." 단, 향수 상세 페이지에 외부 링크 자리를 설계상 남겨둔다(6·7단계에서 반영) |
| W2 | 개인화 추천 알고리즘 | 데이터가 쌓인 후의 문제 |
| W3 | 팔로우/DM/알림 | 소셜 그래프는 콘텐츠 검증 이후 |
| W4 | 네이티브 앱 | 모바일 웹으로 충분 |
| W5 | 평점/별점 시스템 | ★ 점수 경쟁은 "재미" 컨셉과 충돌. 추천 버튼으로 대체 |
| W6 | 비로그인 추천 | 정보 조작(추천 부풀리기) 위험이 이익보다 큼 → §4 미해결 질문 참고 |
| W7 | 자동 콘텐츠 필터링 (AI 모더레이션 등) | 초기 규모에선 신고(S3) + 관리자 삭제(M9)로 충분 |
| W8 | 다국어 지원 | 한국어 우선 |

> **W5 주석**: 별점은 리뷰를 "평가 데이터"로 만들고, 우리는 시향기를 "읽을거리"로 만들고 싶다. 이 결정은 서비스 정체성에 관한 것이므로 뒤집으려면 명시적 논의 필요.

## 3. 비기능 원칙 (Non-Functional Principles)

| # | 원칙 | 구체 기준 |
|---|---|---|
| N1 | **모바일 우선** | 360px 폭 기준으로 먼저 디자인, 데스크톱은 확장. 터치 타깃 44px 이상 |
| N2 | **비로그인 개방성** | 열람 경로에 로그인 벽 없음. 로그인은 "쓰기/추천" 순간에만 요구하고, 그 순간의 이탈을 최소화하는 UX(소셜 로그인 원탭, 작성 중이던 내용 보존)를 갖춘다 |
| N3 | **작성 경험 = 놀이** | 시향기 작성은 "글쓰기 과제"가 아니라 "재미있는 답변 놀이"여야 한다. 유도 질문·선택지·예시 문구로 빈 화면 공포를 없애고, 작성 완료까지의 단계를 짧게 유지한다. 로그인→작성 전환율을 핵심 지표로 추적 |
| N4 | **신뢰 최소선 (조작 방지)** | 추천은 로그인 사용자만, 1인 1추천, 취소 가능. 소셜 로그인으로 1인 다계정 비용을 높인다. 관리자는 모든 게시물·추천 이력에 접근 가능해야 한다 |
| N5 | **빠른 첫 화면** | 모바일 3G 기준 첫 콘텐츠 표시(FCP) 2.5초 이내 목표. 읽으러 온 사람을 기다리게 하지 않는다 |
| N6 | **검색엔진 노출 (SEO)** | 시향기·향수·브랜드 페이지는 서버 렌더링으로 검색 유입 확보 — 비로그인 개방성과 한 몸이며, 커뮤니티 성장(초기 유입)의 주 채널 |
| N7 | **읽기 최적화 타이포그래피** | 본문 16px 이상, 충분한 행간. "읽는 서비스"의 기본기 |
| N8 | **단순한 운영** | 1인 개발/운영 가능한 스택. 관리형 서비스 우선, 서버 관리 최소화 |
| N9 | **콘텐츠 안전 최소선** | 작성 시 커뮤니티 가이드 노출, 관리자 전체 CRUD 권한(M9), 신고 접수(S3). 자동 필터링은 규모가 커진 뒤(W7) |
| N10 | **접근성 기본기** | 시맨틱 마크업, 대체 텍스트, 명도 대비 WCAG AA 수준 |
| N11 | **포트폴리오 품질** | 이 프로젝트는 운영자의 마케팅/IT 역량 증명이기도 하다. 단계별 문서(본 문서 시리즈), ADR, 표준적인 기술 선택, 배포·모니터링 구성을 남겨 "과정 자체"를 보여줄 수 있게 한다 |
| N12 | **수익화 확장 여지** | 지금 구현하지 않되(W1), 향수 상세 페이지의 외부 구매 링크 슬롯·광고 영역을 스키마와 레이아웃 설계에서 미리 자리만 잡아둔다 |

## 4. 미해결 질문 (다음 단계 전 확인 필요)

1. **향수 기초 데이터 수급**: 향수 DB(이름/브랜드/계열)를 어떻게 채울 것인가? — 초기 수동 입력(운영자 시딩) vs 공개 데이터 활용. MVP 규모(예: 인기 향수 100~300개 시딩)로 시작하는 것을 제안.
2. **비로그인 추천 허용 여부**: ✅ **확정(2026-08-07): 로그인 사용자만 추천**(M6, W6). 근거: 비로그인 추천은 추천 수 조작·정보 왜곡 위험이 크고, 추천 수가 큐레이션의 재료이므로 신뢰가 곧 서비스 품질이다. 대신 추천 버튼을 누른 비로그인 사용자를 소셜 로그인으로 자연스럽게 유도하는 전환 장치로 활용한다.
3. **작성 가이드의 구체 설계**: "향수가 사람이라면?" 유도 질문의 종류·순서·필수/선택 여부 — 방향은 확정(M5), 구체 설계는 2단계 User Story와 4단계 와이어프레임에서 다룸. (예: 성별/나이대/직업/성격/어울리는 계절 선택지 + 자유 서술 "이 사람을 소개해 주세요")
4. **서비스 이름/톤**: perfumeishuman("향수는 사람이다")과 "향수가 사람이라면?" 컨셉의 연결 — 확정됨. UI 톤(8단계)에서 "사람 소개하듯 말하는" 문체로 일관되게 반영.
