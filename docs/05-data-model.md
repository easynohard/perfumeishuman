## 0. 읽는 법 · 범위

- **입력**은 4단계 와이어프레임의 화면 요소다. 화면에 그려진 모든 것이 어딘가에서 와야 하므로, 화면을 훑어 데이터 항목을 남김없이 뽑는 것이 이 단계의 일이다.
- 각 화면을 네 갈래로 나눈다.

  | 구분 | 의미 |
  |---|---|
  | **표시** | 화면에 보이는 값 |
  | **입력** | 사용자가 넣는 값 |
  | **파생** | 다른 데이터에서 계산되는 값 (추천 수, 시향기 수 등) |
  | **이면** | 화면에 안 보이지만 그 화면이 동작하려면 필요한 값 (권한, 정렬 키, 상태 플래그) |

- 항목명은 **한국어 개념명**으로 쓴다. 물리 컬럼명·타입·길이·인덱스·제약·관계는 6단계 ERD에서 확정한다.
- 이 문서가 정하는 것은 **"어떤 값이 존재해야 하는가"**까지다. "어떻게 저장하는가"는 6단계다.

### 이번 단계에서 확정한 결정 3가지 (2026-08-31 사용자 승인) ✅

| # | 결정 | 근거 |
|---|---|---|
| **결정 1** | **소셜 로그인 수집은 공급자 구분 + 공급자 회원번호까지**. 이메일·프로필 이미지는 수집하지 않는다 | 개인정보 최소수집. 파기 대상이 줄어 ADR 0008의 익명화가 단순해진다 → **[ADR 0010](./adr/0010-minimal-personal-data-collection.md)** |
| **결정 2** | **게스트 신고 중복 제한은 브라우저 로컬 기록 + 대상별 총량 규칙**. 신고자 IP를 저장하지 않는다 | 신고 때문에 개인정보 수집 항목을 늘리지 않는다. 우회 가능하지만 관리자 수동 처리(M9)가 최종 방어선 → **[ADR 0010](./adr/0010-minimal-personal-data-collection.md)** |
| **결정 3** | **시향기 삭제는 소프트 삭제 + 처리 이력**(삭제 시각·처리 주체·사유) | E1의 "관리자 삭제는 일반 삭제와 구분되어 기록된다"를 스키마 한 벌로 충족. 오삭제 대응·신고 처리 추적이 함께 해결된다 → **[ADR 0011](./adr/0011-soft-delete-reviews.md)** |

**결정 1의 부속 판단**: 공급자가 동의 화면에서 닉네임을 함께 넘기더라도 **저장하지 않는다.** 서비스 닉네임은 최초 로그인 시 자동 생성되므로(C1 AC) 공급자 닉네임은 쓰이지 않는 개인정보가 된다.

## 1. 공통 컴포넌트

### 1.1 시향기 카드 (§1.3 — 피드·목록 전부가 쓰는 최소 단위)

| 구분 | 항목 |
|---|---|
| 표시 | 브랜드명, 향수명(변형 B는 생략), 자유 서술 **전문**(≤100자), 대표 태그 2개(나이대 1 + 성격 1), 작성자 표시명, 추천 수 |
| 이면 | 시향기 슬러그(카드 탭 → 상세), 향수 슬러그(변형 A의 브랜드·향수명 줄), **작성자 탈퇴 여부**(표시명을 링크로 걸지 말지 — D4), 본인 글 여부(MY에서 수정·삭제 버튼), 삭제 여부(목록에서 제외) |
| 파생 | 추천 수, 대표 태그 |

- **대표 태그 선정 규칙**: 나이대는 단일 선택이라 그대로. 성격은 최대 3개 중 1개만 노출하므로 규칙이 필요하다 → **태그 어휘의 고정 표시 순서(§3.7의 정렬값) 중 가장 앞선 것**을 쓴다. 사용자의 선택 순서를 따르지 않으므로 **답변에 선택 순서를 저장할 필요가 없다**(6단계 스키마 단순화). ※ §8-1에서 재확인
- 목록은 어디서나 10개씩 + [더보기](§6-10)이므로, 카드가 나오는 모든 목록에 **정렬 키 + 커서(다음 10개의 시작점)**가 필요하다.

### 1.2 전 화면 공통 (헤더·탭바)

| 구분 | 항목 |
|---|---|
| 이면 | 로그인 여부, 로그인한 사용자 id·표시명, **관리자 권한 플래그**(E1), 현재 화면의 뒤로가기 대상 |

## 2. 게스트 열람 화면

### 2.1 홈 — 피드 `/` (B1·M7)

| 구분 | 항목 |
|---|---|
| 표시 | 시향기 카드 변형 A × 10 |
| 파생 | 없음(카드 내부에 위임) |
| 이면 | **추천순 단일 정렬**(§6-2)의 정렬 키 = 추천 수 + 동점 시 최신순, 다음 페이지 커서, 삭제·비공개 글 제외 조건 |

> 정렬 키가 추천 수이므로 **추천 수는 매 조회 시 계산하지 않고 시향기에 집계값으로 보유한다**(§3.9). 추천/취소 시점에 갱신한다.

### 2.2 홈 — 브랜드로 찾기 `/brands` (A2)

| 구분 | 항목 |
|---|---|
| 표시 | 가나다/알파벳 섹션 헤더, 브랜드 로고, 브랜드명, 브랜드별 향수 수 |
| 파생 | 향수 수 |
| 이면 | 브랜드 슬러그, **정렬용 이름**(한글 초성 그룹핑·영문 정렬을 위해 표시명과 별도 필요), 로고 없을 때의 폴백 |

### 2.3 홈 — 계열로 찾기 `/notes` (A3)

| 구분 | 항목 |
|---|---|
| 표시 | 계열명, 계열별 향수 수 |
| 파생 | 향수 수 |
| 이면 | 계열 슬러그, 계열 목록의 **고정 표시 순서**(가나다순이 아니라 운영자가 정한 순서 — 통제 어휘이므로, ADR 0003) |

### 2.4 검색 `/search` (A1·M1)

| 구분 | 항목 |
|---|---|
| 표시 | (향수) 이미지·향수명·브랜드명·시향기 수 / (브랜드) 로고·브랜드명·향수 수 / 인기 향수 목록 / 결과 없음 문구 |
| 입력 | 검색어 |
| 파생 | 시향기 수, 향수 수, **인기 향수 기준값**(= 시향기 수 우선, 동점 시 총 추천 수) |
| 이면 | **향수의 검색용 이름 필드가 한글·영문 둘 다 필요**(A1 — "한글/영문 이름 모두 검색 대상"), 브랜드도 동일, 부분일치 매칭 대상 필드 목록, 이미지 폴백 판단값 |

> 향수·브랜드 모두 **표시명(한글) / 원어·영문명 / 정렬용 이름 / 검색용 별칭**을 구분해 가진다. 검색 품질과 목록 정렬이 여기에 걸려 있다.

### 2.5 브랜드 상세 `/brands/:slug` (A2)

| 구분 | 항목 |
|---|---|
| 표시 | 브랜드 로고·브랜드명·향수 수, 향수 행(이미지·향수명·시향기 수·총 추천 수) |
| 파생 | 향수 수, 향수별 시향기 수, **향수별 총 추천 수**(그 향수의 시향기들이 받은 추천 합계) |
| 이면 | 브랜드 슬러그, 향수 목록 정렬 기준(제안: 시향기 수 → 총 추천 수), 이미지 폴백 판단값, **브랜드 단위 이미지 일괄 비공개 플래그**(ADR 0009) |

### 2.6 계열 상세 `/notes/:slug` (A3)

브랜드 상세와 대칭. 다른 점만 적는다.

| 구분 | 항목 |
|---|---|
| 표시 | 계열명·향수 수, 향수 행에 **브랜드명 병기**(계열 문맥이므로) |
| 이면 | 계열 슬러그, **향수 ↔ 계열은 다대다**(향수 상세에 계열 칩이 여러 개 — §2.7) |

### 2.7 향수 상세 `/perfumes/:slug` (B2·M2)

| 구분 | 항목 |
|---|---|
| 표시 | 향수 이미지(또는 **텍스트 카드 폴백**), 향수명, 브랜드명, 계열 칩(복수), 노트, 시향기 목록 제목 "{향수명}(이)가 사람이라면 (N)", 시향기 카드 변형 B × 10, 빈 상태 문구, **상표 권리 귀속 고지 + 권리 침해 신고 링크** |
| 입력 | 정렬 토글(추천순/최신순 — 이 화면에만 유지, §6-2) |
| 파생 | 시향기 수, 정렬 결과 |
| 이면 | 향수 슬러그, 브랜드 슬러그, 계열 슬러그들, **표시 가능한 이미지가 있는지**(= 이미지 존재 AND 권리 상태 정상 AND 브랜드 일괄 비공개 아님 → §6), **향수명의 받침 유무**(조사 "(이)가·은/는" 자동 처리 — 규칙 처리 가능하므로 저장하지 않음), 외부 구매 링크 슬롯(N12 — **자리만 예약, MVP 미저장**), 다음 페이지 커서 |

- 노트는 **자유 텍스트 한 줄**로 둔다(예: "장미, 리치, 머스크"). 노트별 탐색 화면이 없으므로(계열이 그 역할) 엔티티로 만들 이유가 없다. 필요해지면 6단계 이후에 분리한다.
- 계열은 URL(`/notes/:slug`)을 갖는 **통제 어휘 엔티티**다. 노트와 계열의 이 비대칭이 의도된 설계다.

### 2.8 시향기 상세 `/reviews/:slug` (B3·M3)

| 구분 | 항목 |
|---|---|
| 표시 | 향수 요약 카드(이미지·브랜드명·향수명), 자유 서술 전문, **"이 사람의 프로필" 표**(질문명 + 답변 — 나이대 1개, 성격 1~3개), 작성자 표시명, 작성일, 추천 수, 추천 버튼 상태, "이 향수의 다른 페르소나 (N)" 목록 |
| 입력 | 추천/추천 취소, 신고(사유 4종 택1), (본인 글) 수정·삭제 |
| 파생 | 추천 수, 같은 향수 다른 시향기 수 |
| 이면 | 시향기 슬러그, **내가 이 글을 추천했는지**(버튼 상태 — 로그인 시), **본인 글 여부**(추천 비활성 + "내가 소개한 사람이에요"), 작성자 탈퇴 여부(닉네임 링크 여부), 삭제 여부, SEO 메타(제목·설명·OG 이미지 — N6), 신고 중복 판단값(§2.8 하단) |

- **프로필 표는 "질문명 + 답변"으로 렌더링된다.** 질문 문구가 화면 텍스트로 노출되므로, 태그 질문 자체가 데이터(질문 코드·표시 문구·정렬)로 존재해야 한다(§3.7).
- **신고 데이터**: 대상 시향기, 사유(허위 정보/비방·혐오/스팸·광고/기타), 접수 시각, 신고자(멤버면 사용자 참조, 게스트면 없음), 처리 상태. **신고자 IP는 저장하지 않는다**(결정 2).

### 2.9 작성자 프로필 `/users/:id` (D4·S2)

| 구분 | 항목 |
|---|---|
| 표시 | 닉네임, 소개한 사람 수(시향기 수), 받은 추천 수 합계, 시향기 카드 변형 A × 10(최신순) |
| 파생 | 시향기 수, 받은 추천 합계 |
| 이면 | **공개 프로필 식별자**(URL의 `:id` — 내부 id를 그대로 노출하지 않는 값. 형식은 6단계), **탈퇴 회원이면 이 화면 자체가 열리지 않음**(ADR 0008) |

### 2.10~2.12 정책·안내 `/terms` · `/privacy` · `/help` (F2·F4)

| 구분 | 항목 |
|---|---|
| 표시 | 문서 제목, **시행일**, 본문, 이전 버전 목록(`/terms`·`/privacy`), 하단 권리 침해 신고 링크 |
| 이면 | 문서 종류(약관/처리방침/도움말), **버전 번호**, 시행일, 게시일, 현재 유효 버전 표시, 본문 원문 |

> 약관·처리방침은 **버전을 갖는 데이터**여야 한다. F1의 "동의한 약관 버전이 기록된다"와 F2의 "이전 버전을 확인할 수 있다"가 같은 곳을 가리킨다. `/help`는 버전 관리 대상이 아니다.

## 3. 멤버·입력 화면과 엔티티 후보

### 3.1 로그인 바텀시트 (§3 — 화면 아님)

| 구분 | 항목 |
|---|---|
| 표시 | 트리거별 헤드라인, 소셜 버튼, 복귀 안내, **동의 고지 + 약관·처리방침 링크**, **"탈퇴 후에도 시향기는 익명으로 남는다"** 고지 |
| 입력 | 소셜 로그인 실행 |
| 이면 | **트리거 종류**(쓰기/추천/MY — 문구 분기), **복귀 대상**(직전 화면 + 하려던 행동: 등록할 입력 내용 / 추천할 시향기 id), 현재 유효한 약관·처리방침 버전 |
| 저장 | 로그인 성공 시 → 사용자 계정, **동의 이력**(동의 시각 + 약관 버전 + 처리방침 버전 + 동의 경로) |

### 3.2 시향기 작성·수정 `/write` (D1·D2·M5)

| 구분 | 항목 |
|---|---|
| 표시 | 선택된 향수(이미지·브랜드명·향수명), 커뮤니티 가이드 1줄, 자유 서술 프롬프트, **회전 예시 placeholder**, 남은 글자 수, **질문 카드 버튼 + 랜덤 유도 질문**, 태그 질문 2종과 선택지(나이대 5개 / 성격 12개), 등록 버튼 문구 "내가 아는 {향수명}은/는 이래요", 임시저장 상태 |
| 입력 | 향수 선택(검색), 자유 서술 1~100자, 나이대 1개, 성격 1~3개 |
| 이면 | 진입 경로(향수 선택됨 / 향수 검색부터), 수정 모드 여부(수정 시 향수 변경 불가), **필수 충족 여부**(버튼 활성화 + 미충족 항목 위치), 게스트 여부(등록 시 게이트 분기), **임시저장 내용** |
| 파생 | 남은 글자 수 |

- **임시저장은 브라우저 로컬 보관이다.** 게스트도 입력하므로 서버에 붙일 계정이 없고, 서버 저장은 미완성 글이라는 개인 데이터를 늘린다. 보관 항목: 향수 id, 자유 서술, 선택 태그, 마지막 저장 시각. 등록 성공 시 삭제한다.
- **질문 카드 풀**과 **placeholder 예시 풀**은 사람이 쓴 고정 문구다(W9 무-AI). 문구·활성 여부·노출 순서를 갖는 데이터로 둔다 — 운영 중 문구를 늘리려면 배포가 필요 없어야 한다.

## 5. 부가 산출물 A — 개인정보 항목표

### 5.1 수집 항목

| 항목 | 수집 시점·방법 | 근거 | 이용 목적 | 보관기간 | 탈퇴 시 |
|---|---|---|---|---|---|
| 소셜 공급자 구분 | 최초 로그인 시 자동 | 계약 이행(서비스 이용) | 계정 식별 | 탈퇴 시까지 | **즉시 파기** |

### 5.2 수집하지 않는 항목 (명시)

이메일 · 프로필 이미지 · 실명 · 생년월일 · 성별 · 연락처 · 결제 정보 · **신고자 IP**(결정 2). 만 14세 미만 아동의 개인정보를 별도로 수집·처리하지 않는다.

### 5.3 파기·보존 기준

| 대상 | 처리 |
|---|---|
| 탈퇴 회원의 식별 정보 | 즉시 파기, 복구 불가 (ADR 0008 §2) |
| 탈퇴 회원의 시향기·추천 | 익명 처리 후 보존 — **익명 표시명은 원본 id에서 유도하지 않는 난수** |
| 본인이 삭제한 시향기 | 소프트 삭제 후 **30일 뒤 완전 삭제** (제안 — §8-2) |
| 관리자가 삭제한 시향기 | 소프트 삭제 후 **1년 보존** 뒤 완전 삭제 (제안 — 분쟁 대응) |
| 신고 기록 | 처리 완료 후 **1년** (제안) |
| 관리자 조치 로그 | **3년** (제안 — 운영 감사) |

### 5.4 제3자 제공·처리위탁

MVP 시점 제3자 제공 없음. 소셜 로그인 공급자와 호스팅·데이터베이스 제공자는 **처리위탁**에 해당하며, 공급자·리전 확정은 9단계다. 처리방침의 위탁 목록은 9단계 결과를 받아 8단계에서 확정한다.

## 6. 부가 산출물 B — 향수 이미지 권리 필드

> [ADR 0009](./adr/0009-perfume-image-sourcing-and-takedown.md) §3의 "추적 기록 의무"를 데이터 항목으로 확정한 것이다. 목적은 하나 — **이의가 들어왔을 때 대상 이미지를 즉시 특정하고, 브랜드 단위로 한 번에 내릴 수 있어야 한다.**

### 6.1 이미지 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| 가공 이미지 파일 | ✅ | 정사각 투명 배경 누끼본 |
| **원본 출처 URL** | ✅ | 브랜드 공식 사이트의 원본 위치. **없으면 등록 불가**(관리자 폼 필수 입력) |
| 수집일 | ✅ | 등록 시 자동 기록 |
| 가공일 | ✅ | 누끼 작업일 (자동 또는 입력) |
| 향수 참조 | ✅ | → 브랜드는 향수를 통해 도달 (브랜드 단위 일괄 조치의 경로) |
| **권리 상태** | ✅ | 정상 / 이의접수 / 비공개 / 영구제거 |
| 상태 변경 시각·변경자 | ✅ | 조치 이력 |
| 등록한 관리자 | ✅ | 책임 추적 |
| 대체 텍스트 | ✅ | 접근성(N10) — "{브랜드명} {향수명} 제품 이미지" 자동 생성 가능 |

### 6.2 이의 접수 이력 (별도 기록)

| 항목 | 설명 |
|---|---|
| 접수일 · 접수 경로 | 이메일 등 |
| 대상 범위 | 이미지 단위 / 브랜드 단위 |
| 신청인 표기 | **권리자 또는 대리인 여부만 기록.** 신청인의 개인정보는 최소한으로 보관하고 처리 종료 후 파기 |
| 조치 내용 · 조치일 | 비공개 / 영구제거 |
| 재수집 금지 목록 등재 여부 | → E18 |

- 목표 시간(접수 확인 24시간, 조치 72시간 — ADR 0009 §4)의 준수 여부가 이 기록으로 확인 가능해야 한다.

### 6.3 폴백 판단 규칙 (파생값)

> **표시 가능한 이미지** = 이미지가 존재하고 AND 권리 상태가 `정상`이고 AND 소속 브랜드가 일괄 비공개가 아님

이 값이 거짓이면 향수 상세·검색 결과·브랜드 상세·계열 상세·시향기 상세의 향수 요약 카드가 **전부 텍스트 카드로 폴백**한다(ADR 0009 §5, 4단계 확정 14). 폴백은 선택이 아니라 **즉시 제거를 비용 없는 선택으로 만드는 조건**이므로, 이미지 없이 각 화면이 정상 동작하는 것이 데이터 설계의 요구사항이다.

## 8. 미결 — 검토 요청

1. **대표 태그 선정 규칙**(§1.1): "성격 태그 어휘의 고정 표시 순서 중 가장 앞선 것"으로 제안한다. 이 규칙을 쓰면 답변에 선택 순서를 저장하지 않아도 된다. 사용자가 **먼저 고른 것**을 대표로 삼고 싶다면 선택 순서 저장이 필요하다.
2. **삭제·신고·로그 보관기간**(§5.3): 본인 삭제 30일 / 관리자 삭제 1년 / 신고 1년 / 조치 로그 3년을 제안값으로 넣었다. 처리방침에 그대로 실릴 숫자이므로 확정이 필요하다.
3. **향수 목록 기본 정렬**(§2.5): 브랜드·계열 상세의 향수 목록을 "시향기 수 → 총 추천 수" 순으로 제안한다. 신규 등록 향수가 계속 아래로 밀리는 문제가 있어, 초기 운영에서는 다른 기준(가나다순)이 나을 수도 있다.
