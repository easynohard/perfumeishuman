## 0. 역할(페르소나) 정의

| 역할 | 정의 | 할 수 있는 것 |
|---|---|---|
| **게스트** (비로그인 방문자) | 검색·SNS·지인 추천으로 유입된 사람. 대부분 완전 입문자 | 모든 콘텐츠 열람 + 작성 폼 진입·입력. 시향기 **등록(제출)**·추천은 불가 (시도 시 로그인 유도, 입력 내용은 보존) |
| **멤버** (로그인 사용자) | 소셜 로그인을 마친 사람. 시향기 작성자이자 추천자 | 게스트 권한 + 시향기 작성/수정/삭제(본인 글), 추천/추천 취소, 회원 탈퇴 |
| **탈퇴 회원** | 탈퇴로 계정이 익명화된 사람. 더 이상 이용자가 아니다 | 없음. 남긴 시향기는 `user_NNNNNN`으로 표시되며 수정·삭제는 관리자만 가능 (F3, ADR 0008) |
| **관리자** | 운영자 본인 | 모든 권한 + 전체 게시물 CRUD, 향수/브랜드 데이터 관리 |

> 권한 원칙: 게스트 → 멤버 전환은 "쓰거나 추천하고 싶어진 순간"에만 요구한다(N2). 열람 경로에는 어떤 로그인 벽도 없다.

## Epic A. 탐색 — 향수를 찾는다

### A1. 향수 검색 (M1)

> 게스트로서, 향수 이름이나 브랜드로 검색해서 그 향수가 "어떤 사람"인지 보고 싶다. 시향하러 가지 않아도 이미지를 알 수 있도록.

**Acceptance Criteria**
- [ ] 모든 화면 상단에서 검색에 진입할 수 있다.
- [ ] 향수 이름(한글/영문), 브랜드 이름으로 검색하면 일치·부분일치 결과가 나온다.
- [ ] 검색 결과에는 향수명, 브랜드, 대표 이미지, 시향기 수가 보인다.
- [ ] **이미지가 없는 향수는 향수명·브랜드명 텍스트 카드로 대체되며, 레이아웃이 깨지지 않는다** (ADR 0009 폴백).
- [ ] 결과가 없으면 "아직 등록되지 않은 향수예요"와 함께 인기 향수 목록을 보여준다 (빈 화면으로 끝내지 않는다).
- [ ] 로그인 없이 동작한다.

### A2. 브랜드별 탐색 (M1)

> 게스트로서, 특정 브랜드의 향수 목록을 훑어보고 싶다. 이름은 몰라도 브랜드는 아니까.

**Acceptance Criteria**
- [ ] 브랜드 목록 화면이 있다 (가나다/알파벳 순).
- [ ] 브랜드를 선택하면 그 브랜드의 향수 목록이 나온다.
- [ ] 각 향수 항목에 시향기 수와 총 추천 수가 보인다.

### A3. 계열/태그 탐색 (S1)

> 완전 입문자인 게스트로서, 이름도 브랜드도 모르지만 "시트러스" 같은 분위기로 향수를 둘러보고 싶다.

**Acceptance Criteria**
- [ ] 계열(시트러스, 플로럴, 우디, 머스크 등) 목록에서 선택해 향수를 필터링할 수 있다.
- [ ] 계열은 향수 데이터에 관리자가 지정한 값을 사용한다 (자유 태그 아님 — MVP 단순화).

## Epic B. 읽기 — 시향기를 즐긴다

### B1. 홈 피드 (M7)

> 목적 없이 들어온 게스트로서, 첫 화면에서 바로 재미있는 시향기를 만나고 싶다. 검색할 생각이 없어도 구경하게 되도록.

**Acceptance Criteria**
- [ ] 홈 첫 화면에 시향기 카드 피드가 뜬다 (추천순 기본, 최신순 전환 가능).
- [ ] 카드에는 자유 서술 전문(최대 100자라 카드에 그대로 들어감), 대표 태그, 향수명·브랜드, 추천 수, 작성자 닉네임이 보인다.
- [ ] 카드를 누르면 시향기 상세로 이동한다.
- [ ] 무한 스크롤 또는 더보기로 계속 읽을 수 있다.
- [ ] 모바일(360px)에서 카드 1열 레이아웃으로 깨짐 없이 보인다.

### B2. 향수 상세 페이지 (M2)

> 게스트로서, 향수 하나를 골랐을 때 기본 정보와 그 향수의 "사람들"(시향기들)을 한 화면에서 보고 싶다.

**Acceptance Criteria**
- [ ] 향수명, 브랜드, 대표 이미지, 계열, (있다면) 노트 정보가 보인다.
- [ ] **이미지가 없거나 권리 이의로 제거된 경우 텍스트 카드로 폴백하며, 페이지의 나머지 기능은 정상 동작한다** (ADR 0009 — 즉시 제거를 비용 없는 선택으로 만드는 조건).
- [ ] **상표 권리 귀속 고지와 권리 침해 신고 창구가 하단에 노출된다.**
- [ ] 그 향수의 시향기 목록이 추천순/최신순으로 정렬 가능하게 나온다.
- [ ] 시향기가 0개면 "이 향수의 첫 번째 사람을 소개해 주세요" 작성 유도가 나온다.
- [ ] "시향기 쓰기" 버튼이 화면에서 항상 접근 가능하다 (모바일 하단 고정 등 — 4단계에서 확정).
- [ ] 외부 구매 링크 영역의 자리가 레이아웃에 예약되어 있다 (MVP에서는 비노출 — N12).

### B3. 시향기 상세 (M3)

> 게스트로서, 시향기 전문을 로그인 없이 읽고 싶다.

**Acceptance Criteria**
- [ ] 시향기의 모든 내용(선택지 답변 + 자유 서술)이 로그인 없이 보인다.
- [ ] 어떤 향수에 대한 글인지 향수 정보가 함께 보이고, 향수 상세로 이동할 수 있다.
- [ ] 작성자 닉네임과 작성일이 보인다.
- [ ] 추천 수와 추천 버튼이 보인다 (동작은 C2 참고).
- [ ] 같은 향수의 다른 시향기로 이어지는 목록이 하단에 있다 ("계속 읽게 되는" 경험 — 1.6).
- [ ] URL을 공유하면 로그인 없이 같은 화면이 열린다 (SEO/공유 — N6).

## Epic C. 참여 — 로그인하고 반응한다

### C1. 소셜 로그인 (M4)

> 게스트로서, 쓰거나 추천하고 싶어진 순간에 복잡한 가입 절차 없이 바로 시작하고 싶다.

**Acceptance Criteria**
- [ ] 소셜 로그인 공급자 1개(카카오 우선, 9단계에서 확정)로 로그인할 수 있다.
- [ ] 이메일/비밀번호 가입은 없다.
- [ ] 최초 로그인 시 닉네임이 자동 생성되고, 즉시 변경할 수 있다.
- [ ] **로그인 버튼 영역에 약관·개인정보처리방침 동의 고지가 함께 표시된다** (F1). 고지 없이 가입이 완료되지 않는다.
- [ ] 로그인 후에는 **직전에 하려던 행동으로 돌아간다** (추천을 누르려 했다면 그 시향기로, 작성 중이었다면 작성 화면으로 — N2).
- [ ] 로그아웃할 수 있다.

### C2. 시향기 추천 (M6)

> 멤버로서, 재미있게 읽은 시향기에 추천을 눌러 작성자에게 반응을 보내고 싶다.

**Acceptance Criteria**
- [ ] 멤버는 시향기당 1회 추천할 수 있고, 다시 누르면 취소된다.
- [ ] 추천 수가 즉시 반영되어 보인다.
- [ ] 본인 글에는 추천할 수 없다.
- [ ] **게스트가 추천을 누르면** 로그인 유도 화면(바텀시트 등)이 뜨고, 로그인을 마치면 그 추천이 자동으로 반영된다 (전환 장치 — §4.2 확정 사항).
- [ ] 게스트에게도 추천 수는 항상 보인다.

## Epic D. 쓰기 — "사람"을 소개한다 (서비스의 심장)

### D1. 시향기 작성: 가이드 플로우 (M5)

> 멤버로서, 글솜씨 걱정 없이 유도 질문에 답하다 보면 재미있는 시향기가 완성되면 좋겠다. 빈 화면 앞에서 막막해지지 않도록.

작성은 **한 페이지 스크롤 폼**으로 진행한다 (별도 스텝 이동 없음, 위에서 아래로 자연스럽게 작성):

**① 이 사람을 소개해 주세요 (자유 서술, 최대 100자) — 페이지 상단**
- 프롬프트: "이 향수가 사람이라면, 어떤 사람인지 소개해 주세요"
- **최대 100자** — 짧게 쓰는 것이 기본. 부담을 낮추고, 피드 카드에 전문이 그대로 노출되는 숏폼 콘텐츠가 된다
- 입력창이 비어 있을 때 회전 예시 placeholder 노출 (예: "첫 출근날 긴장한 신입사원 같은 향이에요…")
- "질문 카드" 버튼: 누르면 랜덤 유도 질문 제공 (예: "이 사람의 직업은?", "이 사람이 자주 가는 카페는?", "이 사람의 MBTI는?") — 막힐 때 재미 요소로 사용

**② 이 사람의 프로필 (태그 선택, 탭으로 답변) — 자유 서술 아래로 스크롤하면 등장**
| 질문 | 형식 |
|---|---|
| 이 향수가 사람이라면, 몇 살쯤일까요? | 10대/20대/30대/40대/50대+ 선택 |
| 어떤 분위기의 사람인가요? | 성격 키워드 다중 선택 (예: 차분한, 장난기 많은, 도도한, 다정한, 신비로운 … 최대 3개) |

**Acceptance Criteria**
- [ ] 향수 상세에서 "시향기 쓰기"를 누르면 해당 향수가 선택된 상태로 작성이 시작된다.
- [ ] 게스트도 로그인 없이 작성 화면에 진입해 자유 서술·태그를 입력할 수 있다. **등록(제출)을 시도하는 순간**에만 로그인 유도가 뜨고, 로그인 완료 시 입력해 둔 내용 그대로 자동 등록된다.
- [ ] 작성 화면은 스텝 이동 없는 한 페이지이며, 자유 서술이 상단에, 태그 질문들이 그 아래에 배치된다.
- [ ] 필수 항목은 **자유 서술(1~100자) + 태그 선택(각 질문에서 최소 1개)**. 100자를 넘으면 입력이 제한되고 남은 글자 수가 보인다.
- [ ] 태그 질문은 모두 탭 몇 번으로 답할 수 있다 (타이핑 없음).
- [ ] 자유 서술 입력창에 예시 placeholder가 보이고, "질문 카드" 버튼으로 랜덤 유도 질문을 받을 수 있다.
- [ ] 작성 중 내용은 자동 임시저장되어, 이탈 후 돌아와도 복원된다 (N2/N3).
- [ ] 등록하면 시향기 상세로 이동하고, 홈 피드·향수 상세에 즉시 노출된다.
- [ ] 작성 화면 진입 시 커뮤니티 가이드 요약 1줄이 보인다 (예: "실제 인물 비방·허위 정보는 삭제됩니다" — N9).

### D2. 내 시향기 수정/삭제 (M5)

> 멤버로서, 내가 쓴 시향기를 고치거나 지우고 싶다.

**Acceptance Criteria**
- [ ] 본인 글에만 수정/삭제 버튼이 보인다.
- [ ] 수정 시 작성 폼에 기존 내용이 채워진 채 열린다.
- [ ] 삭제는 확인 절차를 거치며, 삭제된 글은 목록·피드에서 사라진다.

### D3. 내 시향기 모아보기 (M8)

> 멤버로서, 내가 쓴 시향기들과 받은 추천 수를 한눈에 보고 싶다. 반응이 쌓이는 걸 보는 게 계속 쓰는 이유가 되도록.

**Acceptance Criteria**
- [ ] "내 시향기" 화면에서 내가 쓴 글 목록을 최신순으로 볼 수 있다.
- [ ] 각 글의 추천 수와 **총 받은 추천 수 합계**가 보인다.
- [ ] 목록에서 각 글의 상세/수정으로 이동할 수 있다.

### D4. 작성자 공개 프로필 (S2)

> 게스트로서, 재미있는 글을 쓴 사람의 다른 시향기도 몰아 읽고 싶다.

**Acceptance Criteria**
- [ ] 시향기의 작성자 닉네임을 누르면 그 사람의 공개 프로필(닉네임 + 시향기 목록 + 총 추천 수)이 열린다.
- [ ] 로그인 없이 열람 가능하다.
- [ ] **탈퇴 회원의 표시명(`user_NNNNNN`)은 링크로 동작하지 않고 텍스트로만 보인다.** 프로필 페이지도 열리지 않는다 (ADR 0008 — 글이 누적되면 재식별 여지가 생기고, 탈퇴자에겐 "따라 읽기"의 의미가 없다).

## Epic E. 지키기 — 커뮤니티를 보호한다

### E1. 관리자 게시물 관리 (M9)

> 관리자로서, 악의적인 글·거짓 정보·부적절한 콘텐츠를 즉시 수정·삭제하고 싶다.

**Acceptance Criteria**
- [ ] 관리자 계정은 별도 권한 플래그로 구분된다 (관리자 지정은 DB/환경설정 수준 — MVP에서 UI 불필요).
- [ ] 관리자는 모든 시향기를 목록으로 보고 검색할 수 있다 (최신순, 작성자별).
- [ ] 관리자는 모든 시향기를 수정·삭제할 수 있다.
- [ ] 관리자의 삭제는 일반 삭제와 구분되어 기록된다 (사유 메모 가능).
- [ ] 일반 멤버·게스트는 관리자 화면에 접근할 수 없다.

### E2. 관리자 향수/브랜드 데이터 관리 (S4)

> 관리자로서, 향수와 브랜드 데이터를 직접 등록·수정하고 싶다. 콘텐츠의 뼈대는 내가 관리한다.

**Acceptance Criteria**
- [ ] 관리자는 브랜드(이름, 로고)와 향수(이름, 브랜드, 이미지, 계열, 노트)를 등록/수정/삭제할 수 있다.
- [ ] **이미지 등록 시 원본 출처 URL 입력이 필수다.** 수집일이 자동 기록되고, 수집 기준(단순 팩샷만 — 연출컷·모델컷·워터마크 배제) 안내가 입력 폼에 노출된다 (ADR 0009).
- [ ] **재수집 금지 목록에 등재된 브랜드·제품은 등록 시 경고가 뜬다.**
- [ ] **브랜드 단위로 이미지를 일괄 비공개 처리할 수 있다** (권리 이의 대응).
- [ ] 시향기가 달린 향수를 삭제하려 하면 경고가 뜬다.
- [ ] MVP 초기 시딩(인기 향수 100~300개)은 이 기능 또는 스크립트로 수행한다 (§4.1).

### E3. 시향기 신고 (S3)

> 게스트/멤버로서, 부적절한 시향기를 운영자에게 알리고 싶다.

**Acceptance Criteria**
- [ ] 시향기 상세에서 신고할 수 있다 (사유 선택: 허위 정보/비방·혐오/스팸·광고/기타).
- [ ] 신고는 로그인 없이도 가능하되, 동일 대상 중복 신고는 제한한다.
- [ ] 관리자 화면에서 신고 목록과 누적 신고 수를 확인하고 처리(삭제/무시)할 수 있다.

## Epic F. 계정과 고지 — 약속을 지킨다

> 2026-08-16 신설. 소셜 로그인으로 개인정보를 수집하는 이상 동의·철회·고지는 선택이 아니다(N13, M11·M12). 근거: [ADR 0008](./adr/0008-anonymized-retention-on-withdrawal.md)

### F1. 가입 시 약관·개인정보 동의 (M11)

> 게스트로서, 로그인하기 전에 무엇에 동의하는지 알고 싶다. 특히 내가 쓴 글이 나중에 어떻게 되는지.

**Acceptance Criteria**
- [ ] 로그인 바텀시트에 이용약관·개인정보처리방침 링크와 동의 고지가 표시된다.
- [ ] **"탈퇴해도 작성한 시향기는 익명 처리되어 서비스에 남습니다"를 가입 시점에 명확히 고지한다.** 이 고지가 F3의 법적 전제다 (ADR 0008 §5).
- [ ] 각 문서 링크는 새 창 또는 별도 화면으로 열리며, 읽고 돌아와도 로그인 흐름이 끊기지 않는다.
- [ ] 동의 시각과 동의한 약관 버전이 기록된다 (6단계 ERD 반영).
- [ ] 고지·동의 없이 가입이 완료되지 않는다.
- [ ] **소셜 1탭 로그인의 속도를 해치지 않는다** — 별도 동의 화면을 추가하지 않고 버튼 영역 고지로 처리한다 (N2·N3 전환율 보호).

### F2. 약관·개인정보처리방침 열람 (M11)

> 게스트/멤버로서, 언제든 약관과 개인정보 처리 방침을 확인하고 싶다.

**Acceptance Criteria**
- [ ] `/terms`(이용약관), `/privacy`(개인정보처리방침)를 로그인 없이 열람할 수 있다.
- [ ] 두 화면은 MY 화면 하단과 로그인 바텀시트에서 진입할 수 있다.
- [ ] 약관 개정 시 시행일 전 공지하며, 이전 버전을 확인할 수 있다.
- [ ] 각 문서 하단에 권리 침해 신고 창구가 안내된다.

### F3. 회원 탈퇴 (M12)

> 멤버로서, 더 이상 쓰지 않기로 했을 때 내 계정을 정리하고 싶다. 다만 내 글이 어떻게 되는지는 미리 알고 결정하고 싶다.

**화면 형태**: 별도 화면 없이 **MY(`/me`) 안의 확인 모달**로 처리한다 (로그인을 바텀시트로 처리한 3단계 결정과 동일한 결).

**Acceptance Criteria**
- [ ] MY 화면 하단에서 탈퇴에 진입할 수 있다.
- [ ] 확인 모달에서 다음을 **탈퇴 실행 전에** 명확히 안내한다.
  - 계정 정보(소셜 계정 식별자·닉네임)는 즉시 파기된다
  - 작성한 시향기와 누른 추천은 `user_NNNNNN` 형태로 익명 처리되어 **그대로 남는다**
  - **되돌릴 수 없다.** 재가입해도 이전 글을 수정·삭제할 수 없다
  - 글을 지우고 싶다면 **탈퇴 전에** 직접 삭제해야 한다
- [ ] 확인 절차(체크 또는 재확인 탭)를 거쳐야 탈퇴가 실행된다.
- [ ] 탈퇴 후 작성자 표시는 `user_NNNNNN`(원본 id와 무관한 난수, 유니크)으로 대체된다.
- [ ] 탈퇴자가 누른 추천은 유지되어 **다른 회원의 받은 추천 수가 줄지 않는다** (M8 보호).
- [ ] 탈퇴자의 시향기는 본인 수정·삭제 버튼이 사라지고, 관리자만 처리할 수 있다 (E1).
- [ ] 탈퇴 완료 후 홈으로 이동하며, 로그아웃 상태가 된다.

### F4. 도움말·커뮤니티 가이드 (N9·N13)

> 게스트/멤버로서, 이 서비스를 어떻게 쓰는지와 어디까지 써도 되는지 알고 싶다. 권리 침해를 발견하면 알릴 곳도 필요하다.

**Acceptance Criteria**
- [ ] `/help` 화면에서 서비스 사용법(시향기 쓰는 법, 추천, 태그)을 확인할 수 있다.
- [ ] 커뮤니티 가이드(금지 표현, 실제 인물 비방·허위 정보 금지)가 함께 게시된다 — 작성 화면의 1줄 요약(D1)이 여기로 연결된다.
- [ ] **권리 침해 신고 창구(이메일)와 처리 절차 요약이 안내된다** (ADR 0009).
- [ ] 로그인 없이 열람 가능하다.
